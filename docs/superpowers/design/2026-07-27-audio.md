# Sound design for the nation-ruler game

Design document for the audio of the real-time nation-ruler game.
Scope: the sound inventory tied to real protocol messages, the layering and mixing rule that survives
x8 and four nations, ambience and pause, the implementation surface, the determinism boundary, and the
asset policy for audio.
Not in scope: any change to `packages/server/` or `packages/shared/`; music; voice; N3 diplomacy and
N4 ruler-voice sounds, which are named where they would attach and left undesigned.

Companion deliverable: `audio-staging/` — nine vetted CC0 candidate files, seven alternates, licences,
a manifest, and the normalisation script. Nothing in it is in the repository.

> document's §7 and the same reasoning as `2026-07-27-asset-policy.md`: no asset enters the tree before the

## Part 1 — Findings

### 1.1 There is no audio in this project, at all

Verified rather than assumed. Across the whole tree excluding `node_modules` and `.git`:

- **zero** files with any audio extension (`.mp3 .ogg .wav .m4a .flac .aac .opus .webm .mid .midi .aiff .wma`);
- **zero** occurrences of `AudioContext`, `webkitAudioContext`, `new Audio(`, `HTMLAudioElement`,
  `howler`, `@pixi/sound`, `pixi-sound`, `playSound`, `audioSprite`;
- **zero** word-boundary matches for `sound`, `audio`, `sfx`, `bgm` or `音` in any source file, test,
  document or spec — including the Japanese specs, which never raise the subject;
- `packages/client/package.json` declares exactly three dependencies: `@agent-town/shared`,
  `pixi.js`, `vite`.

So this is a greenfield surface with one inherited constraint and one inherited precedent. The constraint
is `AGENTS.md:20`: *"No new asset files."* The precedent is that all 396 vendored PNGs are Kenney CC0
(`docs/superpowers/design/2026-07-27-asset-policy.md`), which is where the collection went first.

### 1.2 The speed multiplier is not the only source of the problem — the wire shape is

The brief frames x8 as the design problem. It is, but the mechanism is more specific than "everything
happens eight times faster", and the specifics decide the design.

```
packages/shared/src/constants.ts:6    export const TICK_RATE = 10;              // sim ticks per second
packages/shared/src/constants.ts:315  export const NATION_TICKS_PER_SEASON = 300;  // 30 s at x1
packages/shared/src/constants.ts:317  export const SPEED_MULTIPLIERS = [0, 1, 2, 4, 8] as const;
packages/shared/src/constants.ts:319  export const CLOCK_BROADCAST_MS = 1000;   // wall-clock heartbeat
packages/shared/src/constants.ts:79   export const WORLD_POLITY_COUNT = 4;
```

A season is 300 ticks at 10 ticks/second = 30 s at x1, therefore **3.75 s at x8**. Four nations.

Now the part that is not in the brief. From the frozen protocol
(`docs/superpowers/plans/2026-07-27-n1-living-nations.md:194-215`):

```ts
export type ServerMessage =
  | { type: "welcome"; state: NationWorldState }
  | { type: "clock"; tick: number; year: number; season: Season; speed: SpeedMultiplier }
  | { type: "season"; tick: number; year: number; season: Season;
      nations: NationState[]; changedCells: WorldCellChange[] }
  | { type: "orders"; tick: number; nationId: NationId; autoPilot: boolean;
      options: DirectiveOption[]; queued: …; chancellorChoice: …; rejected: … };
```

and the plan's own commentary (`:225`):

> `clock` is a light heartbeat, emitted on a wall-clock interval so its rate does not change with game
> speed, and carries no nation state. **Nation state changes only at season boundaries, so `season` is
> the only message that carries `nations`.**

Four consequences, and each one removes work the design would otherwise have to do:

1. **Every world event is already coalesced by the wire.** Famine, directive completion, stock changes,
   score changes, rank changes for all four nations arrive inside *one* `season` message. There is no
   stream of individual events to rate-limit — there is one message, and the design's whole job is to
   decide how many onsets that message is allowed to authorise. The answer below is *at most one*.
2. **`clock` cannot drive sound at all.** It is 1 Hz at every speed by construction and carries no
   nation state. A clock-tick sound would be a metronome that lies about the game speed.
3. **At x0 there is nothing to hear from the world.** `season` never fires while paused and `clock`
   carries no content, so `orders` is literally the only message with information in it. This is not a
   design choice to make about pause; it is a fact about the protocol that the mix should mirror (§4.2).
4. **`changedCells` is empty in N1** (`:225`), so a territory-change cue cannot fire and is not designed.

`docs/superpowers/plans/2026-07-27-n1-living-nations.md:229` also pins the `orders` trigger set, which is
what makes the acknowledgement cue possible and slightly tricky:

> `orders` is therefore emitted on an accepted `selectNation`, on **every** `issueDirective`,
> `cancelDirective` and `setAutoPilot` whatever the outcome, and **once after each `season`**.

That last clause means `orders` is not purely player-initiated. §5.3 resolves it.

### 1.3 The visual design already solved this problem, and the solution transfers

`docs/superpowers/design/2026-07-27-visual.md` §2.4 states the calm rule as a budget:

> **One motion class per event class, motion always decays to a static readable state, and nothing that
> is not changing ever moves.** At any instant the map animates at most: the cells that changed this
> season, plus one season crossfade. Nothing else, ever.

Three specific moves in that section are the ones worth copying, and one is worth copying exactly:

- **The season boundary was moved out of the transient channel.** It is *"one whole-map crossfade of the
  layer-2 season wash, 600 ms"*, and the document names what that buys: *"One season boundary every 30 s
  at x1, affecting the whole map uniformly, is calm by construction — it is a tide, not an event."*
  The audio analogue is the single most important decision in this document (§3.1).
- **Construction gets no motion at all**, with an explicit reason: *"A quantity that changes every 30
  seconds does not need to be animated to be noticed; animating it would spend the motion budget on the
  calmest thing on the map."*
- **An explicit silence list**: *"Deliberately not animated: score changes, population changes, stability
  changes, rank changes."* This design inherits that list verbatim, which is why rank change makes no
  sound (§5.2). It is not an aesthetic preference; it is consistency with a decision already taken.

One further piece of prior art, from `docs/superpowers/design/2026-07-27-hud.md` §1.8, is a trap this
design must not walk into:

> `survivalViewModel.ts` / `societyViewModel.ts` schedule transient messages by **tick** … At nation
> scale that breaks at x0: a tick-scheduled toast never expires while paused, and at x8 it expires 8×
> faster in wall-clock.

An audio envelope scheduled in ticks has exactly that defect twice over: at x0 a release never completes
and the voice hangs forever; at x8 an attack compresses into a click. §6.4 draws the boundary.

Finally, `hud.md` §3.1a states the intent behind the speed control, which the mixing rule leans on:

> **x8 is for watching, x1–x2 for governing, x0 for thinking.**

### 1.4 What the naive design would actually sound like

Worth quantifying before designing, because it sets the target. Sound every event, for every nation:
one boundary chime, plus a completion for each nation that finished a directive, plus a famine cue, plus
a cue per row that moved in the ranking. Directive durations are 1–3 seasons
(`constants.ts:372`, `NATION_DIRECTIVE_DURATIONS`), so with four nations under chancellor control
roughly two directives complete per boundary; a single rank swap moves two rows.

| speed | boundary interval | boundaries/min | naive onsets/min | arriving as |
|---|---|---:|---:|---|
| 0 | — | 0 | 0 | — |
| 1 | 30.0 s | 2 | ~10 | 2 clumps of ~5 |
| 2 | 15.0 s | 4 | ~20 | 4 clumps of ~5 |
| 4 | 7.5 s | 8 | ~40 | 8 clumps of ~5 |
| 8 | **3.75 s** | 16 | **~80** (worst case ~208) | 16 clumps of ~5 |

The failure is not the average rate. It is the clumping: five onsets inside a few milliseconds, sixteen
times a minute. That is the machine gun, and no volume setting fixes a clump.

## Part 2 — The two governing rules

Everything in Part 3 onwards is an application of these.

### 2.1 The x8 rule: information about a continuous world lives in a sustained layer, never in onsets

> **Only two things may produce an onset: an action the player just took, and a crisis in the player's
> own nation. Everything the world does on the clock is expressed as a change in a sustained layer that
> has no attack.**
>
> Mechanically: (a) rival nations are silent, unconditionally; (b) one `season` message authorises **at
> most one** onset, chosen by priority, never a queue; (c) that onset must additionally clear a
> wall-clock budget of 5000 ms, and a cue that fails the budget is **dropped, not queued**.

Clause (a) is the one that does the heavy lifting, and it is a correctness argument rather than a mixing
preference. Spec §3.5 requires that *"他国について見えるのは公開情報のみとする"*, and `hud.md` §4.6 already
declines to render rival stocks, active directives and reports for that reason. A rival's famine is a
`SeasonLedgerReason` inside a rival's `SeasonReport` (`packages/shared/src/nation.ts:67`, `:79`) — it is
not public. **Sounding it would leak information the HUD deliberately refuses to draw.** So the ×4
multiplication in §1.4 does not need mitigating; it needs deleting, and the spec deletes it.

Clause (b) is the direct analogue of visual.md's *"at any instant the map animates at most: the cells
that changed this season, plus one season crossfade"*. One message, one cue. The cue is *composed* from
the message, not queued from it:

```
priority for the single season onset (highest wins, ties impossible):
  2  crisis.famine        own nation's lastReport has an entry with reason "famine"
  1  directive.completed  own nation's lastReport.completedDirectiveIds is non-empty
  0  (none)               silence — the bed crossfade carries the boundary
```

A season in which two directives complete *and* a famine strikes produces **one** bell. The count and
the detail are in the report panel and the decision strip, which is where counting belongs.

Clause (c) — why 5000 ms, specifically. The boundary interval is 30 000 / 15 000 / 7500 / 3750 ms at
x1/x2/x4/x8. Any budget in the open interval (3750, 7500] leaves x1–x4 completely untouched and admits
exactly every other boundary at x8. 5000 ms sits inside that window with 1.25 s of margin against a
`season` message arriving late and 2.5 s against one arriving early, so network jitter cannot flip the
behaviour. **One rule, no `switch (speed)` anywhere in the code** — the speed-dependence is an emergent
consequence of a wall-clock budget meeting a speed-dependent message rate.

What the player actually hears:

| speed | boundary interval | boundaries/min | world onsets/min | dropped by the budget |
|---|---|---:|---:|---|
| 0 | — | 0 | **0** | — (`season` never fires) |
| 1 | 30.0 s | 2 | **≤ 2** | none |
| 2 | 15.0 s | 4 | **≤ 4** | none |
| 4 | 7.5 s | 8 | **≤ 8** | none |
| 8 | 3.75 s | 16 | **≤ 8** | every other boundary |

**The world's audible event rate saturates at 8 per minute and does not rise above x4.** Against §1.4's
~80/min at x8, that is a factor of ten, and the clumping is zero because the bus is monophonic and one
message authorises one cue.

Dropping rather than queueing matters and is worth stating on its own. A queue at x8 drains after the
state it describes has already been superseded — the player hears a famine bell for a season that is two
seasons in the past. That is worse than silence, because it is a lie. And dropping is aligned with the
player's own declared intent: `hud.md` §3.1a says x8 is for watching, so a player at x8 has chosen to
stop governing, and the visual channel (report strip, ranking, world map) keeps carrying everything.

### 2.2 The pause rule: at x0 the world goes still, not silent — and the desk becomes the only voice

> **At speed 0 the bed's *motion* component fades to zero over 600 ms while its *place* component holds
> at full level and its *season* component freezes. The desk bus is untouched. So the mix inverts: the
> world stops breathing and the order desk becomes the only thing that can make a sound.**

Both failure modes named in the brief are avoided by construction rather than by tuning:

- **Dead silence reads as a crash.** It cannot happen: `bed.place` never fades except on mute.
- **Ambience at full level reads as the game not noticing.** It cannot happen either: the thing that
  fades is specifically the component whose only job is to mean *time is flowing*. Its absence is
  therefore not a level change, it is a statement.

The inversion is not a stylistic flourish; it mirrors the protocol exactly (§1.2, consequence 3). At x0,
`season` never fires and `clock` carries no state, so `orders` is the only message with content — and
`orders` is the only trigger the desk bus has. The mix is loudest, relatively, in exactly the place the
wire is still alive. This also makes the game's most important guarantee audible: the N1 plan added
`orders` precisely because *"a paused player issuing a directive would see nothing, and a rejected order
would be indistinguishable from an accepted one"* (`:229`). At x0, that acknowledgement is not competing
with anything.

600 ms is not a new number: it is `WORLD_MAP_SEASON_FADE_MS` from visual.md §2.4's proposed constants, so
the pause fades on screen and in the ears over the same interval and reads as one event.

## Part 3 — Ambience

### 3.1 The bed is three synthesised components, and the season boundary is a crossfade

There is one sustained layer, always present while a nation is selected and audio is unmuted, at a level
low enough that it is noticed on being removed rather than on being added. It has three components, and
their separateness is the whole reason it works:

| component | what it means | responds to | never |
|---|---|---|---|
| `bed.place` | the world exists | nothing | fades, except on mute |
| `bed.season` | which season it is | `season` message — 600 ms crossfade | steps discontinuously |
| `bed.motion` | time is flowing | `clock.speed === 0` → 0; resume → nominal, both 600 ms | changes *rate* with speed |

**The season boundary produces no onset.** It re-targets `bed.season` and crossfades over 600 ms. This is
the audio form of visual.md's *"it is a tide, not an event"*, and it is what makes x8 survivable: a
crossfade has no attack transient, so four of them in fifteen seconds is a drifting texture, not four
dings. The four target states reuse the season identity the project already has — visual.md §2.4 makes
the point that using the same four constants at both scales *"is the single strongest continuity cue"* —
so the bed's four states are the audible siblings of `SEASON_GROUND_TINTS`, tilted the same direction:
spring open and bright, summer full, autumn warm and narrowing, winter thin and airy. Concretely that is
a filter cutoff and a harmonic balance, not four recordings.

**`bed.motion`'s rate is fixed and does not scale with speed.** This is a deliberate refusal. A pulse
that ran eight times faster at x8 would be the machine gun re-introduced through the sustained channel,
and the game speed is already stated in the clock bar and in the countdown's rate of fall. Motion's only
job is presence/absence.

### 3.2 Why the bed is synthesised and not a file

This is the audio analogue of the asset policy's *"Procedural `Graphics` is the default for anything on
the 16 px grid"*, and the reasoning has the same shape — it is about what the medium can and cannot do,
not about taste:

- The bed must **crossfade between four states on an arbitrary schedule**. A file gives one state; four
  seasonal variants means four files, four decodes and four gain nodes to achieve what one filter
  parameter does.
- `bed.motion` must **fade independently of `bed.place`**. Independence is only available if they are
  separate voices, which for a file means splitting the bed into two recordings that must not phase
  against each other.
- A synthesised bed **loops perfectly by construction.** There is no seam, because there is no loop point.
- The bed is the only long sound in the design, so synthesising it is what lets §7 put a hard ceiling on
  audio file length at all: **every committed file is a transient, gated at ≤ 1.0 s**, and the nine staged
  cues in fact measure **0.097 s to 0.697 s**. Had the bed been a file, the ceiling would have to be tens
  of seconds and would constrain nothing.

Files remain the right answer for the transients, for the mirror-image reason: a struck bell has a timbre
an oscillator does not credibly invent, exactly as an image generator does not credibly produce a 1 px
outline in one exact colour.

### 3.3 Level, ducking, and why volume is not the lever

The bed sits well under the cues. When a world-bus cue is admitted, the bed **ducks by 4 dB over 80 ms,
holds for the cue's length, and recovers over 400 ms**. Ducking is the structural alternative to loudness:
it makes a quiet cue clearly audible without the cue itself being loud, so the same file works at x1 with
a calm bed underneath and at x8 where cues are rarer and the ear is less primed. Desk-bus cues do not
duck — they are the player's own action and are already at the front of the mix.

## Part 4 — The inventory

### 4.1 What sounds

Nine files, three synthesised components. Every row names the message it fires on, so nothing here is
triggered by a guess about state.

| # | slot | fires on | bus | source of truth | why it earns a sound |
|---|---|---|---|---|---|
| 1 | `bed.place` | `welcome` + nation selected | bed | — | The world exists. Its removal is what makes pause and mute legible. |
| 2 | `bed.season` | `season` (crossfade, **no onset**) | bed | `season.season` | The boundary is the game's only decision boundary; it must be felt. Putting it in the sustained channel is what makes x8 possible (§2.1). |
| 3 | `bed.motion` | `clock.speed` crossing 0 | bed | `clock.speed` | Pause is a legitimate way to play and must be audible without silence (§2.2). |

### 4.2 What is deliberately silent

This list is longer than the one above, which is the point.

| left silent | why |
|---|---|
| **The season boundary as an onset** | Moved to the bed crossfade. This is the x8 rule (§2.1) and the single decision the whole design rests on. §8.1 offers the tunable if it proves underwhelming. |
| **Rank change in the prosperity table** | Two independent reasons. visual.md §2.4 already puts rank change on the deliberately-not-animated list, and rank moves because *rivals* moved — so a rank cue is a rival's action reaching into the player's ears, which §2.1 clause (a) forbids on public-information grounds. |
| **Everything about rival nations** — their famines, completions, directives, stocks, scores | Spec §3.5 public information only; `hud.md` §4.6 already refuses to render it. Sounding it would leak what the HUD declines to draw. This is what deletes the ×4. |
| **Directive *issued*** (the button press) | The response sounds, not the press. `c1-nation-client.md:163`: *"Do not fake acknowledgement optimistically — that is precisely what lies to the player at speed 0."* A click on press followed by an acceptance 10 ms later at x0 also just sounds like one smeared noise. So the submit button carries no `data-audio-cue`: it is the one control whose press genuinely commits something and still says nothing, because the server gets to answer first. |
| **Score, population, stability, culture, wealth deltas** | Continuous quantities. visual.md §2.4's silence list, inherited. Also: they change every single season for every nation, so they are the definition of "not an event". |
| **Territory change / `changedCells`** | `changedCells` is empty in N1 by contract. Deferred to N3 with the war model, the same way visual.md defers contested cells. Named here so nobody implements a cue that can never fire. |
| **The chancellor's automatic seasonal choice** | It happens for up to four nations every season and it is the *default*. A sound for the default is a sound for nothing. `chancellorChoice` is already visible in the commit slot for the whole season. |
| **`welcome`, and therefore reconnect** | **Hard rule.** `wsClient`'s reconnect is silent and re-sends `welcome` (`hud.md` §1.5, §3.6), and the HUD *"must not assume it has seen every intervening `season`"*. Any cue derived from `welcome` would burst on every reconnect — the machine-gun failure triggered by a network event instead of by speed. `welcome` sets state and sounds nothing. |
| **Navigation** — arrow keys, `Tab`, focus moves, hover, scroll, world-map cursor movement | The cursor moves 96×64 cells; a per-cell tick is the fastest machine gun available and it is driven by the player's hand, so no budget saves it. Navigation is not a commit. |
| **DOM panel open/close** — directive panel (`D`), season report (`R`), chronicle (`C`), rival panel | Reading surfaces, opened by the player who knows they pressed the key. The season report especially: it is replaced in place at every boundary, so a panel cue would double the boundary cadence. The city view is different in kind — it is a *scene* cut with no animation (#10). |
| **The clock heartbeat and the countdown** | 1 Hz at every speed by construction, and `hud.md` §3.5 already declines to announce the countdown in the live region for the same reason: *"a live region that re-announces every second is unusable."* |
| **Speed changes between 1/2/4/8** | The press gets `ui.commit` and nothing more. Pause and resume are different — they get the bed change (#3), which is a sustained statement rather than an onset. |
| **Nation selection at game start** | The bed fading in over 1200 ms *is* the game starting. It is also the gesture that unlocks the AudioContext (§5.4), so it is load-bearing without needing a cue of its own. |
| **The LLM ruler (N4)** | Named for completeness. An 元首 speaking is content, and `hud.md` §6 already establishes that nothing in the client degrades without it. No cue. |
| **Music** | No requirement asks for it, it is the largest possible asset, and a 30-second decision loop with a repeating track is the fastest route to a muted tab. |

### 4.3 Audio is never the sole carrier

`hud.md` §3.5 already specifies a live region that announces *"order accepted or rejected with the
reason, autopilot flipped, speed changed, season resolved with its one-line headline, nation selected."*
The sounding set above is close to a subset of that announcing set, which is a useful corroboration
rather than a coincidence — both were derived from "what did the player need to know that is not already
on screen".

The invariant: **every cue is redundant.** Muted audio loses no information, and no state is
distinguishable by ear alone. That is why `autopilot.toggle` can use one file for both directions, and
why the mute control costs the design nothing.

## Part 5 — The implementation surface

### 5.1 Web Audio API, no new dependency — and the Pixi sound plugin is structurally wrong here

**Recommendation: the Web Audio API directly.** Two reasons, one governance and one architectural.

The governance reason: `c1-nation-client.md:39` and `:232` both say *"No new dependencies"*, and
`AGENTS.md:18` requires a commit-body justification for any dependency. Nothing in this design needs one.

The architectural reason is the stronger of the two and would hold even if dependencies were free.
A Pixi sound plugin binds audio to the Pixi `Application`, and in this client the Pixi surface is
**only the local city view**, which is mounted and unmounted:

- the world map is Canvas 2D (`worldMapView.ts:273 renderWorldMapCanvas`, mounted into DOM at
  `worldChronicle.ts:376`), and `c1-nation-client.md:45` decides *"The world map stays Canvas 2D. Pixi
  becomes the local city view's renderer and its only consumer"*;
- `traversal.md` §2.2 makes the city view the sole owner of the single `createWorldViewport`;
- `c1-nation-client.md:191` requires that no second Pixi `Application` be created.

So audio attached to Pixi would live inside a surface that does not exist for most of the game and
disappears every time the player closes the city view — while the bed is required to be continuous
across exactly that transition. The plugin is not merely an extra dependency; it is the wrong lifetime.

Two things Web Audio gives that matter here and that an `HTMLAudioElement` approach would not:
sample-accurate gain ramps on a shared bus (the crossfades and the duck), and `AudioContext.currentTime`
as a monotonic scheduling clock (§6.3).

### 5.2 Files

Following the client's established shape — *"a pure tested view model plus a thin DOM controller"*
(`c1-nation-client.md:148`) — with a fourth directory because audio is neither `render/` nor `ui/`.

New, pure (no `AudioContext`, no clock, no DOM, unit-testable):

| file | exports | notes |
|---|---|---|
| `packages/client/src/audio/cueCatalog.ts` | `CueId` union, `CUES: Record<CueId, CueSpec>` where `CueSpec = { file, bus, priority, gainDb, maxDurationMs }`, `AUDIO_BUDGETS` | Data only. The slot→file table the conformance gate checks against. |
| `packages/client/src/audio/cuePlan.ts` | `planSeasonCue(msg, playerNationId)`, `planOrdersCue(msg, outstanding)`, `planBedTargets(season, speed)` | **`planSeasonCue` is a pure function of one `season` message** — it needs no previous snapshot, because famine and completion are both readable from `lastReport` directly. That is what keeps it stateless and reconnect-proof. |
| `packages/client/src/audio/cueBudget.ts` | `admit(state, request, nowMs): { admitted, state }` | The onset budget and the priority-aware debounce. `nowMs` is a parameter, never read. |

New, adapter (the only file allowed to touch the audio API or a clock):

**No DOM controller imports audio.** UI cues arrive through **one delegated `click` listener** on the HUD
root that reads `[data-audio-cue]`. Adding a sound to a new button is an attribute, not an import, and
`directivePanel.ts`, `nationClockBar.ts` and the rest never learn that audio exists.

That mechanism only hears pointers, and `ui.commit`'s entire trigger set — the speed controls and mute —
is **also** bound to keys at document level by `nationKeyboard.ts` (`hud.md` §3.5). Left alone, clicking
`[x4]` would sound and pressing `4` would not, for the same state change. The fix is not a second cue
path but **one fewer**: the keyboard handler for those keys resolves the matching
`button[data-speed="4"]` / the mute button and calls `.click()` on it, instead of invoking `setSpeed` /
`setMuted` itself. Pointer and key then converge on the one code path that already exists, the delegated
listener sees both, and `aria-pressed` / `aria-disabled` state stays in one place. It also means a key
bound to a control the HUD has disabled does nothing, which is the behaviour you want and would
otherwise have to remember to write. Keys that are *not* in `ui.commit`'s trigger set (`A`, `D`, `R`,
`C`, `Escape`, arrows) keep calling their handlers directly — they are silent by §4.2, so there is
nothing to converge.

**This one is an ask, not a decision, and the distinction matters.** `hud.md` §3.5 owns
`nationKeyboard.ts` and its key map; changing how the speed keys reach `setSpeed` is that document's call,
not this one's — the same boundary the `respondingTo` request respects in §5.3. So it is registered for
whoever owns the HUD, with the fallback stated so the audio design is not blocked either way: **if the
redirect is declined, `nationKeyboard.ts` calls `audio.commit()` directly for those six keys**, and the
"no DOM controller imports audio" invariant takes one documented exception in one file. The audio is
correct under both; the redirect is the version with one code path instead of two, which is why it is
the one to ask for first.

Unchanged, and specifically not to be touched: everything under `packages/server/` and
`packages/shared/`, and every frozen resident-scale module.

### 5.3 Pairing `orders` responses to requests, and why the two rejections differ

`orders` fires both on player action and once after every `season` (§1.2). Field-diffing does not
discriminate them reliably: re-issuing the same directive kind changes only `queued.id`, because the
server mints the `DirectiveId` at accept time. So `nationAudio` keeps a small FIFO of outstanding
requests, fed by the `send` wrapper, and applies these rules in order:

```
1. msg.rejected !== null            -> order.rejected      (priority 2, does NOT consult outstanding)
2. outstanding non-empty            -> cue for its kind    (priority 1, consume the entry)
3. otherwise                        -> silent              (this is the post-season echo)
```

Rule 1 not consulting the FIFO is deliberate and is what makes the important case airtight: the
post-season echo always carries `rejected === null`, so a rejection can never be a false positive and
can never be lost to a mis-paired FIFO — the cue the player most needs is the one that does not depend
on bookkeeping.

The residual imprecision, stated rather than smoothed over: if a season boundary lands between an order
being sent and its response, the echo consumes the FIFO entry and the acceptance cue fires on the echo
instead of on the response — milliseconds early, identical in content. If that order was going to be
*rejected*, both cues fire; the priority-aware debounce (§2.1 clause (c), applied to the desk bus with a
60 ms window) keeps the rejection and drops the acceptance, because a higher-priority cue inside the
window **replaces** rather than being dropped.

**One small protocol ask, not a blocker.** A `respondingTo: ClientMessage["type"] | "season"` field on
`orders` would remove the FIFO entirely. Registered here as a request for whoever owns `protocol.ts`, in
the same spirit as visual.md §6's two asks. The design is correct without it; it is just less pretty.

**Speed is the deliberate exception to "never acknowledge optimistically".** `ui.commit` fires on the
*press* of a speed button, before any server round-trip. This is not an inconsistency with §4.2's rule
about the submit button, and the reason is in `hud.md` §2.3: *"`setSpeed` needs no entry: `clock` already
echoes `speed` at roughly 1 Hz at every speed including 0."* An in-range speed cannot be rejected —
`SPEED_MULTIPLIERS` is the button set — so there is no rejection to lie about. A directive, by contrast,
can be rejected for six documented reasons (`DirectiveBlockedReason`), which is exactly why its cue must
wait for the answer.

### 5.4 Autoplay unlock, decoding, and the backgrounded tab

**Unlock.** Browsers require a user gesture before an `AudioContext` may produce sound. The game supplies
one for free: it starts with `playerNationId === null` and a nation picker (`c1-nation-client.md:114`,
`hud.md` §4.2 国選択), so the first click is guaranteed and is semantically the right moment — the bed
fading in over 1200 ms is the game beginning. `context.resume()` goes on that click. No "click to enable
sound" gate, and no attempt to start audio before it.

**Decoding must not repeat the sprite-preload trap.** `main.ts:94` is `await Assets.load([...SPRITE_PATHS])`
at module top level, which `hud.md` risk 6 and `c1-nation-client.md:102` both flag as a real defect.
Audio must not copy it: the nine cues are fetched and decoded **after** unlock, in parallel, and a cue
whose buffer has not arrived is **treated as silent, not queued**. 260 kB decodes in a few milliseconds,
and a missing cue must never block a frame or delay a message.

**Backgrounded tab.** Suspend the context on `document.hidden` and resume on visible. Two constraints:
this must never send `setSpeed` — `hud.md` §6 is explicit that *"The player owns the speed control; a HUD
that takes it is a HUD that lies about who is in charge"* — and the world bus's last-onset timestamp must
be reset on resume, because `AudioContext.currentTime` does not advance while suspended and would
otherwise make the first cue after a long background look like a 200 ms-old repeat.

**Mute.** A toggle in the clock bar plus `M`, persisted to `localStorage`. Recommended default: **on**,
because §4.3 guarantees audio carries no unique information, so a first-time player loses nothing either
way and a game that starts silent is usually assumed broken. This is one constant and the owner may
reasonably prefer default-off for the `just dev` loop; nothing else in the design changes.

## Part 6 — Determinism and purity

The project holds a hard line here, so the boundary is stated as invariants with the mechanism that
enforces each.

### 6.1 The simulation never learns audio exists

Nothing under `packages/server/` or `packages/shared/` changes: no field, no constant, no flag. Audio is
a read-only consumer of messages that already exist.

`packages/shared/src/constants.ts` in particular gains **nothing**. Every audio number — cue gains,
crossfade durations, the 5000 ms budget, the 60 ms debounce, the 4 dB duck — is a presentation value, and
`c1-nation-client.md:97` settles which side of the line that is: *"Presentation values (colours, pixel
sizes, easing durations) are not game constants and live in the client."* So this design needs no
stop-and-report on a simulation-owned file. The one genuinely game-shaped number it reads,
`NATION_TICKS_PER_SEASON`, it does not read at all — the `season` message is the signal.

### 6.2 Audio can never influence the game

- `audio/` **must not import `net/wsClient.js`**, so it has no channel to send a `ClientMessage`. It
  observes outbound messages through the `send` wrapper and never calls one. Mechanically checkable with
  `rg` and a good candidate for the existing `Date.now`/`Math.random` determinism scan
  (`handoff/2026-07-27-delegation.md:35`) rather than a review convention.
- No view model imports from `audio/`, and `audio/` imports no view model. The dependency is
  one-directional: `main.ts` → `audio/`.
- Audio never mutates HUD state, never writes to the live region, never changes speed.

### 6.3 Where the wall clock is allowed, and which clock it is

Sound is presentation, so it may read a clock. The boundary:

- `cuePlan.ts`, `cueBudget.ts`, `cueCatalog.ts` contain **no** `Date.now()`, `performance.now()`,
  `Math.random()` or `AudioContext`. Every time value arrives as an explicit `nowMs` parameter, which is
  what makes the budget testable with literal timestamps and no fake timers.
- `mixGraph.ts` is the **only** file that reads a clock, and the clock it reads is
  **`AudioContext.currentTime`**, not `Date.now()` or `performance.now()`. That is deliberate: it is the
  clock the graph schedules its own ramps against, so a budget decision and the envelope it authorises
  cannot drift apart, and it stops advancing while the context is suspended, which handles the
  backgrounded tab correctly for free (with the one caveat in §5.4).
- Consequently `nationAudio` needs **no `tick(now)` loop of its own** — unlike the countdown, which needs
  one because it interpolates between heartbeats (`hud.md` §4.8). Audio is entirely message-driven, so it
  adds no `requestAnimationFrame` work and does nothing at all while paused.

### 6.4 Tick domain versus wall-clock domain

The one rule that prevents the `hud.md` §1.8 trap:

> **Cue *selection* is a pure function of message content. Cue *scheduling* is wall clock only.
> Nothing in audio is ever scheduled by tick.**

A tick-scheduled envelope fails twice: at x0 the release never completes and the voice hangs forever; at
x8 the attack compresses into a click. Note this is the *opposite* of visual.md §2.4's choice, which puts
map-change lifetimes in ticks *so they compress with the clock*. That divergence is correct and worth
stating: a visual decay that compresses is still legible, whereas a compressed audio envelope is a
different sound. Same problem, opposite answer, because the media differ.

## Part 7 — Asset policy for audio

The analogue of `docs/superpowers/design/2026-07-27-asset-policy.md`, and stricter, because audio has a
failure mode art does not: a non-conforming file is not merely ugly, it is *late* or *loud*, and both
read as bugs in the game rather than as flaws in the asset.

### 7.1 What is vendored, and the measured facts that set the gate

Nothing yet. The staged candidates come from three Kenney packs, all **CC0 1.0 Universal**, verified by
reading `License.txt` from inside each downloaded zip rather than from a listing page — same source and
same licence as the three sprite packs already under `packages/client/public/assets/`.

Two measured facts about those 284 files decide the policy, and they are the direct counterpart of the
asset policy's *"Alpha is only ever 0 or 255"* and its off-by-one colour tail:

**The packs are not internally consistent.** Two sample rates (Interface Sounds and Impact Sounds at
44 100 Hz, RPG Audio at 48 000 Hz). Mixed channel counts *within* one pack — Interface Sounds has mono
`click_001.ogg` and stereo `select_001.ogg`, `pluck_001.ogg`, `switch_001.ogg`, `error_001–004.ogg`,
`drop_001–004.ogg`.

**Levels and onsets vary by more than a design can absorb.** Peaks from **0.0 dBFS** (RPG Audio
`metalLatch`, `bookPlace1`, `doorOpen_1`, `handleCoins` — full scale) down to **−11.5 dBFS**
(`bookOpen`); leading silence from **0 ms** to **54 ms** (`handleCoins`). A 54 ms head on an
acknowledgement cue is a 54 ms lie about server latency at speed 0.

So, exactly as with the sprites: *a gate that demanded conformance of the packs themselves would flag the
packs.* The gate therefore applies to the **committed output of the normalisation step**, never to the
pack. Same lesson, learned before writing the test rather than after.

### 7.2 The policy

**Licence is a gate, not a note.** Every audio directory ships the pack's original `License.txt`, exactly
as the three sprite packs do, plus a manifest entry per file recording source URL, pack name and version,
licence, slot, and measured duration. No file whose licence cannot be verified from the source enters the
tree — and "verified" means read from inside the artefact, not inferred from a badge on a web page.

**Synthesis is the default for anything sustained; files are for percussive character.** §3.2 argues it
from what each medium can do. The consequence is checkable, and the enforced number and the measured
number are deliberately not the same one: item 4 below gates **every committed file at ≤ 1.0 s**, while
the nine staged cues measure **0.097–0.697 s**. The headroom is there so a future cue with a longer decay
does not need the policy rewritten; the measured spread is the evidence the ceiling is not being leaned
on. **And there is no music** — that one is absolute, not a threshold.

**Commit WAV, not OGG — because the gate is only dependency-free if the container is parseable.** This is
the one place this policy diverges from what the packs ship, and the reason is the same reason the asset
policy could assert its PNG gate needs *"no new runtime dependency"*: items 1–4 of §7.3 need the 44-byte
RIFF header and the PCM samples, which is a `Buffer` and arithmetic. An OGG Vorbis gate would need a
decoder, so it would degrade to "the file exists and is under N kB", which checks nothing that matters.
The cost is measured and small: **260 kB for nine mono cues**, against 1.6 MB of already-vendored PNGs.

**Normalisation is a deterministic post-process, not an instruction.** `audio-staging/normalise-cues.sh`
downmixes to mono, resamples to 44 100 Hz, trims leading silence below −50 dBFS, peak-normalises to
−12.0 dBFS and writes 16-bit PCM WAV. Verified, and the scope of the verification stated exactly:
re-running the script over all nine slots from the untouched pack files produced output that is
**md5-identical for 9 of 9 cues** on ffmpeg 8.1. Not a spot check — every committed cue. The script is
committed alongside its output, as the asset policy requires of the quantise step.

Reproduce it:

```sh
S=audio-staging/_source
bash audio-staging/normalise-cues.sh /tmp/repro ui-commit=$S/interface-sounds/Audio/click_001.ogg …
for f in audio-staging/cues/*.wav; do
  [ "$(md5 -q "$f")" = "$(md5 -q "/tmp/repro/$(basename "$f")")" ] || echo "DRIFT: $f"
done
```

Honest caveat, and a second reason the committed format is WAV: byte-reproducibility holds for PCM output
on a fixed ffmpeg build. It would **not** hold for re-encoded OGG Vorbis across libvorbis versions, so
the asset policy's *"Regenerating must produce the same bytes"* is a claim lossy audio cannot support.

### 7.3 The conformance gate

For every file under `packages/client/public/audio/`, in a Vitest test with no new dependency:

1. **format** — 16-bit PCM WAV, **1 channel**, **44 100 Hz** (RIFF header);
2. **peak** — **−12.0 dBFS ± 0.5 dB**;
3. **leading silence** below −50 dBFS — **≤ 10 ms**;
4. **duration** — within the slot's `maxDurationMs` in `cueCatalog.ts`, and **≤ 1.0 s** absolutely;
5. **slot bijection** — every `CueId` resolves to a file that exists, and every file is claimed by
   exactly one `CueId`. No orphans, no dangling slots;
6. **provenance** — the directory has a `License.txt`, and every file has a manifest entry with a
   non-empty `licence` and `sourceUrl`.

Item 3's threshold is **calibrated, not aspirational**: eight of the nine staged cues measure 0 ms, and
`city-view-open.wav` measures 5 ms because it is a time-reversed decay whose onset is genuinely a ramp
rather than padding. A 0 ms gate would fail a correct file. That is the same trap the asset policy
avoided when it declined to demand an exact palette.

With this gate in place, provenance stops mattering — pack, synth, script or human, a non-conforming file
fails `just check`. Without it, "the cues are consistent" is a hope that decays with every file added.

### 7.4 Governance: what has to change before any of this is committed

`AGENTS.md:20` currently says *"No new asset files"*, flatly. That is the right default while no gate
exists, for exactly the reason the asset policy gives: it makes a worker stop and report rather than
improvise. So, stated plainly: **nothing in `audio-staging/` may be committed until the §7.3 gate exists
and `AGENTS.md:20` is amended** — to something like *"no new asset files that do not pass their
conformance test"*, which is the same amendment the art pipeline will need.

The gate is the cheap part. It is one test file over nine WAVs.

## Part 8 — Risks, and what I could not settle without hearing it

### 8.1 The bet this design makes, and the tunable if it loses

**Risk 1 — "the boundary makes no sound at all" may read as underwhelming at x1.** This is the design's
central bet (§2.1, §3.1) and the one I cannot verify from a table. The hybrid falls out of the existing
budget with no special case: keep the crossfade at every speed, and additionally admit a **very quiet**
onset at priority 0 when the world bus's 5000 ms budget allows. That makes the boundary audible at x1 and
x2 (30 s and 15 s gaps), present at x4 (7.5 s, just inside), and **automatically absent at x8** — one
constant, no `switch (speed)`. It is a two-line change and it is where I would look first.

*Listen for:* at x1, does a boundary with nothing happening in it feel like an event or like nothing?
And at x8, does the bed read as **a slow seasonal drift or as a pulsing wobble**? If it wobbles, the
fallback is to bind `bed.season` to the *year* instead of the season — a year is 30 s at x8 and 2 min at
x1, which turns four crossfades per fifteen seconds into one.

### 8.2 Judgements that need a listen, each with a staged alternate

Every one of these has a file in `audio-staging/alternates/` and a named question in `manifest.json`.
I could not audition anything; the picks are justified on measured duration, sample rate, channel count,
peak, RMS and leading silence, plus one sample-level comparison.

**Risk 2 — `order.accepted` versus `directive.completed` is the load-bearing pair.** One means "recorded,
commits at the next boundary", the other "it paid off". If they blur, the game's only verb has no
feedback loop. I deliberately picked them from different timbral families (`confirmation_001` vs
`glass_004`) rather than two members of one family for this reason. *Listen for:* played back to back,
is the distinction obvious in under a second?

**Risk 3 — does a bell read as an alarm or as a reward?** `crisis.famine` is a struck bell, which
tradition uses for both. `alternates/crisis-famine__ALT-dull-thud.wav` has no pitch to be pleasant with.
*Listen for:* does the famine cue make you look at the report, or feel like you scored?

**Risk 4 — is the refusal tolerable on repeat?** `order.rejected` is the quietest of eight error files
for exactly this reason. *Listen for:* press a blocked directive ten times in a row.

**Risk 5 — do nine files from two packs recorded a year apart sound like one instrument or like a
folder?** This is the question a single-file audition cannot answer and the one most likely to send the
shortlist back. The identity I was aiming at is a chancery — paper, latch, coin, bell — rather than a
sci-fi interface, and Kenney's Interface Sounds pack sits closer to the latter. If the set reads as
generic UI, the reserve is Kenney RPG Audio (already downloaded, `_source/rpg-audio/`), whose
`bookPlace`, `metalLatch`, `clothBelt` and `handleCoins` are diegetic and material — at the cost of
48 kHz stereo sources with full-scale peaks, which the normalisation step handles but which means
re-measuring everything.

**Risk 6 — the absolute level of the bed.** Every number in §3.3 (4 dB duck, 80/400 ms, the bed's
nominal gain) is reasoned, not heard. The bed is supposed to be noticed on being removed, not on being
added, and that threshold is per-listener and per-hardware.

### 8.3 Risks I own, and things blocked on someone else

**Risk 7 — `orders` request/response pairing.** §5.3 makes the rejection cue airtight without any
protocol change and leaves one harmless imprecision. A `respondingTo` field would remove it. Registered
as a request, not a blocker.

**Risk 8 — nothing here is testable end-to-end until C1-3 lands.** `wsClient` cannot even send today
(`hud.md` §1.5: *"No `send`. The whole client is receive-only"*) and the reshaped protocol is N1 Task 5's.
The pure modules (`cuePlan`, `cueBudget`, `cueCatalog`) are testable immediately against hand-built
`season` and `orders` literals; the adapter is not testable without a browser at all, which is why so
little logic lives in it.

**Risk 9 — the city-view cues assume the docked-pane cut.** `traversal.md` §2.2 decides it and
`c1-nation-client.md:47` confirms it, so this is settled — but it is the one inventory row whose entire
justification is "there is no animation to carry the transition". If the transition ever becomes a camera
move, `view.cityOpen`/`Close` lose their reason to exist and should be cut rather than kept.

**Risk 10 — audio on a 30-second loop, forever.** `hud.md` risk 8 already names report fatigue at
30-second seasons. Audio inherits that risk and mitigates it the same way: the boundary itself is silent
(§2.1), only the player's own famine and own completion sound, and the ceiling is 8 world onsets per
minute at any speed. If playtesting still finds it too much, the next lever is to raise the world budget
from 5000 ms — which is a one-constant change that degrades gracefully in exactly the direction the
player will want.

**Risk 11 — I did not verify browser behaviour of anything.** No code was written and no browser was
opened. The autoplay-unlock claim (§5.4), the `AudioContext.currentTime` suspend behaviour (§6.3) and
WAV decodability via `decodeAudioData` are all standard and well documented, but they are stated here
from knowledge rather than from a test in this project.
