## 1. Findings about the existing client idiom

### 1.1 Two rendering stacks already coexist, and the world map is *not* PixiJS

`main.ts` mounts Pixi for the resident scene and two screen overlays:

```ts
app.stage.addChild(world, infoBubbleLayer, hudLayer, tickerLayer);
```

but the 96×64 world map — the nation game's actual board — is drawn with plain Canvas 2D into a DOM
`<canvas>` living inside the chronicle panel:

```ts
// ui/worldMapView.ts
export function renderWorldMapCanvas(canvas: HTMLCanvasElement, view: WorldMapViewModel): void {
  canvas.width = view.width * WORLD_MAP_CELL_SIZE_PX;
  canvas.height = view.height * WORLD_MAP_CELL_SIZE_PX;
  const context = canvas.getContext("2d");
  if (context === null) return;
  context.imageSmoothingEnabled = false;
  drawTerrain(context, view);
  drawPolityOverlays(context, view.cells);
  drawRoutes(context, view);
  drawCities(context, view);
  drawSettlement(context, view);
}
```

**Consequence for this design:** the nation-scale main view is the existing Canvas 2D renderer promoted
from a side panel to the primary scene. No Pixi is needed at nation scale in N1. Pixi stays in the tree
and comes back only when the traversal design mounts the local scene. This is the reuse path the spec asks
for (`worldMapView` is listed as **流用**), and it is what makes the HUD survive the scale change: the HUD
is DOM, the scene is a swappable canvas underneath it.

Pointer hit-testing already works under CSS scaling, because it is expressed in terms of the element's
bounding box rather than pixels:

```ts
export function worldMapPositionFromPointer(
  view: WorldMapViewModel,
  bounds: Pick<DOMRect, "left" | "top" | "width" | "height">,
  clientX: number, clientY: number,
): Position | null
export function polityIdAtWorldMapPosition(view: WorldMapViewModel, pos: Position): string | null
```

`polityIdAtWorldMapPosition` already returns `null` for sea cells. Cell → nation selection is therefore
free.

### 1.2 Text-heavy panels are DOM; Pixi is used only for the scene and two thin overlays

`inspectPanel.ts` and `worldChronicle.ts` are DOM builders over `document.createElement`, with a private
`createElement(tag, className, text?)` helper in each, `section()` / `textLine()` / `textList()` helpers,
and BEM-ish class names styled by the inline `<style>` block in `packages/client/index.html`. `hudLayer.ts`
and `tickerLayer.ts` are the only Pixi text surfaces, and both are ~60-line "destroy and rebuild"
functions:

```ts
export function renderHudLayer(layer: Container, state: WorldState): void {
  for (const child of layer.removeChildren()) child.destroy({ children: true });
  const viewModel = buildSurvivalHudViewModel(state);
  ...
}
```

The nation HUD is tables, meters, buttons, and scrolling reports. It belongs in DOM, following
`inspectPanel`/`worldChronicle`, not in Pixi following `hudLayer`. That adds no dependency, so the
"No new dependencies. PixiJS." constraint is satisfied.

### 1.3 The established shape: pure view model + thin DOM controller + JSON-key dedupe

```ts
export interface InspectPanelController {
  show(target: InspectTarget, world: WorldState): void;
  close(): void;
}
export function createInspectPanel(root: HTMLElement, onClose: () => void): InspectPanelController
```

with re-render suppression and state preservation that must be copied verbatim in idiom, because a
30-second HUD re-renders constantly:

```ts
const nextKey = `${nextTargetKey}:${JSON.stringify(viewModel)}`;
if (!root.hidden && nextKey === renderedKey) return;
const sameTarget = !root.hidden && nextTargetKey === renderedTargetKey;
const preserved = preservedPanelState(root, sameTarget);   // { restoreCloseFocus, scrollTop }
```

`preservedPanelState` restores `scrollTop` and refocuses `.inspect-panel__close` if focus was inside.
Without this, a `season` message every 30 s would eject keyboard focus from the directive panel and reset
its scroll. This is the single most important carry-over in the whole file.

`worldChronicle.ts` establishes the controller variant with `isOpen()` and focus return:

```ts
export function createWorldChronicle(root, onClose, returnFocus?): WorldChronicleController
export function bindWorldChronicleEscape(controller, onEscape): () => void
```

`bindWorldChronicleEscape` attaches to `document` and returns an unbind. That is the precedent for
document-level global keys.

### 1.4 Accessibility conventions are already set and are cheap to keep

- One live region: `<div id="world-status" role="status" aria-live="polite" aria-atomic="true">`, written
  through `announce(message)` in `main.ts`.
- Tabs use `role="tablist"`/`role="tab"`/`aria-selected`/`aria-controls` (`chronicleTabs()`).
- Meters use native `<progress>` with `aria-label` + `aria-valuetext`
  (`createNeedsList`: `meter.setAttribute("aria-valuetext", \`最大${need.max}中${need.valueLabel}\`)`).
- Toggles use `aria-pressed` (`traffic-overlay-toggle`), disclosures `aria-expanded`
  (`chronicle-toggle`).
- Every button has `min-height: 44px` in CSS.
- There is **no `<input>` or `<textarea>` anywhere in `index.html`** — so document-level single-key
  shortcuts are safe, with the one collision noted in §3.5.

### 1.5 `wsClient.ts` physically cannot send

```ts
export interface WebSocketLike {
  onmessage: ((event: { data: string }) => void) | null;
  onclose: (() => void) | null;
}
interface ConnectionHandlers {
  onWelcome(state: WorldState): void;
  onUpdate(state: WorldState): void;
}
```

No `send`. The whole client is receive-only today, and it also owns the diff-application logic
(`applyUpdate` splices `changedTiles`/`changedTrailCells` into a local copy). Both facts matter:
the nation HUD needs an outbound channel, and `applyWorldCellChanges` for `changedCells` should live in
the same place `applyUpdate` does.

Reconnect exists and is silent: `socket.onclose = () => setTimeout(open, RECONNECT_DELAY_MS)`, and the
server re-sends `welcome`, which today runs `replaceState` and resets everything.

### 1.6 `NationState` has no name and no colour

```ts
export interface NationState { id: NationId; controller: NationController; autoPilot: boolean; ... }
```

Names, colours, `values`, `taboo`, `foundingMyth`, `governance`, `ambition` come from
`history.polities` (`Polity`), joined by id — exactly the join `worldMapView.buildCells` already does:

```ts
const polityColors = new Map(history.polities.map(({ id, color }) => [id, hexColor(color)] as const));
```

Every nation-scale view model therefore takes `(nation, polity)` or `(nations, history)`, never `nation`
alone. `Polity.taboo` is free-form Japanese prose, which is what makes the `"taboo"` blocked reason
explainable — see §3.4.

### 1.7 `moveTileCursor` is the one scale-free piece of the keyboard module

```ts
export function moveTileCursor(cursor: Position, key: string, worldWidth: number, worldHeight: number): Position
```

Fully parameterised — it works on 96×64 unchanged. Its neighbours do not:

```ts
import { TILE_SIZE } from "../render/mapLayer.js";
export function resolveKeyboardTarget(world: WorldState, deathEvents: DeathEvent[], knownResourceKinds, cursor)
export function keyboardActivationAction(activeTarget: InfoBubbleTarget | null, nextTarget: InfoBubbleTarget)
```

`resolveKeyboardTarget` is bound to `WorldState` and to `TILE_SIZE` from `render/mapLayer.js`, which pulls
Pixi and the sprite sheet into the module graph. So importing `moveTileCursor` from `keyboardNavigation.ts`
would drag Pixi into the nation bundle. See §4.9 for the resolution.

The two-step activation rule it establishes — *first activation shows a bubble, second activation on the
same target opens the panel* — is worth preserving as an interaction grammar even though `InfoBubbleTarget`
itself is resident-scale:

```ts
return nextKey !== null && activeKey === nextKey ? "open-inspect" : "show-bubble";
```

### 1.8 The ticker's scheduling idiom is the right model for transient nation events, in the wrong units

`survivalViewModel.ts` / `societyViewModel.ts` schedule transient messages by **tick**
(`expiresAtTick: death.tick + TICKS_PER_DAY`, `visibleFromTick`/`expiresAtTick` merged queues). At nation
scale that breaks at x0: a tick-scheduled toast never expires while paused, and at x8 it expires 8× faster
in wall-clock. Nation-scale transients must be scheduled in wall clock (`performance.now()`), or — better,
and what this design chooses — **not be transient at all** (§3.3).

### 1.9 `main.ts` is at its complexity ceiling

790 lines, eight dirty flags (`mapDirty`, `trailsDirty`, `structuresDirty`, `deathsDirty`, `tickerDirty`,
`hudDirty`, `historyDirty`, `agentsDirty`, plus `infoBubbleDirty`), one `state: WorldState | null`, and
`AGENTS.md` enforces "cognitive complexity ≤ 10 (Biome enforces)". Adding nine nation panels here will not
pass. The nation HUD must be one composition root (`ui/nationHud.ts`) exposing four apply-methods, so
`main.ts` grows by roughly six lines.

Two smaller couplings to retire with the resident HUD:

- `main.ts` imports `HUD_PANEL_HEIGHT` from `hudLayer.ts` to place the ticker
  (`positionTicker`: `HUD_PADDING + HUD_PANEL_HEIGHT + TICKER_HUD_GAP`). Both go away together.
- `await Assets.load([...SPRITE_PATHS])` is a **top-level await before `app.init`**. If the resident scene
  is unmounted in N1, this pays the resident sprite-sheet cost on every nation-game start. Move it behind
  the traversal-time local-scene mount.

## 2. Two contract gaps that block the deliverable

Both are in `protocol.ts`, which Task 5 reshapes anyway. Neither touches `nation.ts`. The plan says
"If a contract looks wrong, stop and report instead of editing it" — this is the report.

`bfebc09 docs: adopt the two-scale map and split package ownership`, committed while this design was being
written, makes that the only available move: the client worker owns `packages/client/` and
"never edits `packages/shared/` or `packages/server/`", with `protocol.ts` named as the boundary Codex
defines and the client consumes — "a missing protocol field is a stop-and-report". §2.1, §2.2 and §2.4 below
are therefore addressed to the simulation owner, not proposals this design may implement.

### 2.1 `DirectiveOption` is defined and never transmitted

```
$ rg -n "DirectiveOption|listDirectiveOptions" packages/ --glob '!node_modules' --glob '!dist'
packages/shared/src/nation.ts:33:export interface DirectiveOption {
packages/shared/test/nation.test.ts:26:    const option: DirectiveOption = {
```

The frozen wire is `welcome | clock | season`. `NationWorldState` carries `nations`, not options.
`NationState` carries `activeDirectives: ActiveDirective[]` — what is *running*, never what is *offered*.
`listDirectiveOptions(nation, polity, worldMap)` is a server function (plan Task 3). Meanwhile §8.4 forbids
the client from judging availability, and Task 6 requires a panel showing 候補・コスト・所要季数・国柄適合・不可理由.

**As frozen, the directive panel — the game's only real verb — cannot be built.**

### 2.2 At x0, nothing ever acknowledges an order

`clock` carries no nation state. `nations` ships only on `season`. Player directives "queue and take effect
at the next season boundary" (plan Task 5). Therefore at speed 0 there is no `season` message, ever, and
`issueDirective`, `cancelDirective` and `setAutoPilot` produce **no observable authoritative change at all**.
Rejected orders — unknown nation, unaffordable, blocked, wrong nation, all rejected server-side per Task 5 —
are indistinguishable from accepted ones. This collides head-on with "pausing at x0 is a legitimate way to
play".

`setSpeed` is the exception and needs no fix: `clock` is broadcast on a `CLOCK_BROADCAST_MS = 1000`
wall-clock interval and carries `speed`, so it keeps arriving at ~1 Hz even at x0 with a frozen tick.
Speed echoes within a second. Autopilot's only echo is `NationState.autoPilot` on `season` — 30 s away at
x1, never at x0.

### 2.3 Proposed resolution: one new server message, the order desk

```ts
// packages/shared/src/protocol.ts — additive to the Task 5 reshape
| {
    type: "orders";
    tick: number;
    nationId: NationId;                 // always the client's own nation
    autoPilot: boolean;
    options: DirectiveOption[];         // finally uses the frozen contract, unchanged
    queued: { id: DirectiveId; kind: DirectiveKind; targetCityId: string | null } | null;
    chancellorChoice: { kind: DirectiveKind; targetCityId: string | null } | null;
    rejected: DirectiveBlockedReason | "notYourNation" | "unknownNation" | null;
  }
```

Emitted on: accepted `selectNation`; **every** `issueDirective` / `cancelDirective` / `setAutoPilot`
whatever the outcome; and once after each `season`. Nothing else.

Why each field earns its place:

- `options` — closes §2.1 with the existing contract, and because nation state only changes at boundaries,
  the list is a stable authoritative snapshot the player can deliberate over indefinitely at x0.
- `queued` + `rejected` — closes §2.2. Round-trip acknowledgement at any speed, including 0. `rejected`
  non-null with `queued` unchanged is an unambiguous "no", with the reason already resolved server-side.
- `queued.id` — **the server mints the `DirectiveId` at accept time, not at the boundary.** Three payoffs:
  `cancelDirective(id)` works uniformly on queued and active directives (otherwise a queued order is
  uncancellable, because it has no id yet); the client can attribute an `ActiveDirective` to the player vs
  the chancellor by remembering ids it queued, with no contract change; and N2's causal inspector gets a
  stable key from the moment of decision.
- `chancellorChoice` — the requirement-5 payload. The chancellor is pure and deterministic, and nation state
  does not change mid-season, so its choice is **exact for the whole season, not a guess**. This is what
  lets the HUD always answer "what will commit at the next boundary" (§3.2).
- `autoPilot` — its only other echo is 30 s away, or never at x0.

Symmetry check (§3.5 of the spec, プレイヤーとエージェントは対等): the chancellor default is the nation's own
internal advisor, identical machinery for every nation. In N4 the LLM 元首 must be given the same
`chancellorChoice` in its prompt context, or the player gains an information edge.

Smaller-diff alternative if a new message type is refused: fold `options` into `season`, and answer
`selectNation` by re-sending `welcome` with `playerNationId` set. That closes §2.1 only. §2.2 then has to be
faked client-side with optimistic rendering plus a wall-clock timeout, which cannot distinguish a rejection
from a slow server and will lie to the player at x0. Not recommended.

### 2.4 Prosperity component semantics must be pinned, not hedged

```ts
export interface ProsperityScore {
  population: number; production: number; wealth: number; stability: number; culture: number;
  /** Weighted total, 0..1000. */
  total: number;
}
```

Only `total` is documented. Whether the five components are raw metrics or normalised ratios is
unresolvable from the contract, and it decides whether the breakdown is renderable at all — reconstructing
the normalisation client-side is exactly what §8.4 forbids. This is a semantic choice inside `number`, not a
field change, so it can be fixed without editing the contract. **Require: components are the normalised
0..1 ratio against their fixed reference constant.** Owner: plan Task 4 (`prosperity.ts`), asserted in its
tests.

The client then renders each component's *contribution* as `weight × component × 1000`, importing the weight
constants from `@agent-town/shared` (the same way it already imports `WORLD_MAP_POLITY_ALPHA` and
`HUNGER_MAX`), and **always displays `prosperity.total` verbatim as the total**. If rounded contributions do
not sum to `total`, the server's `total` wins and the client does not reconcile. A view-model test should
assert that no code path sums contributions into a displayed total.

### 2.5 Rivals are not redacted on the wire

`season` ships `NationState[]` in full, so rival `stocks`, `activeDirectives` and `lastReport` reach every
browser. The frozen `NationState` has no public-only variant, so this design does not restructure around it.
The HUD renders only this public set for rivals, and nothing else:

> name, colour, `controller`, `prosperity.total` + the five components, `population`, `territoryCellCount`,
> `cities[].{cityId, population, developmentLevel}`, and the `Polity` prose the chronicle already shows.

Deliberately not rendered for rivals: `stocks`, `activeDirectives`, `lastReport`, `autoPilot`, `stability`,
`culture`. Risk, stated plainly: a player who opens devtools sees everything. Server-side redaction of the
`season` payload is the real fix and belongs to N3 when diplomacy makes hidden information matter.

## 3. The interaction model

### 3.1 The season is a deliberation window; the boundary is a commit point

This is the whole answer to "real time never stops, but the decision arrives every 30 s". The decision is
**not** made at the boundary. Orders can be issued at any moment during the season and queue for the
boundary. So there is no reaction test and nothing to be ambushed by — provided the HUD says three things
at all times:

1. how long until the commit,
2. what will commit,
3. that a new order replaces the queued one, at no cost, until the commit lands.

The countdown is deadline awareness, not a timer to race.

Countdown derivation, client-side, from `clock`:

```
boundaryTick   = (floor(clock.tick / NATION_TICKS_PER_SEASON) + 1) * NATION_TICKS_PER_SEASON
elapsedTicks   = (now - clockReceivedAt) * TICK_RATE * clock.speed / 1000        // TICK_RATE = 10
predictedTick  = min(clock.tick + floor(elapsedTicks), boundaryTick - 1)
remainingTicks = boundaryTick - predictedTick
remainingMs    = clock.speed === 0 ? null : remainingTicks * 1000 / (TICK_RATE * clock.speed)
```

**Hard rule: local prediction may approach the boundary but never cross it.** Only a `season` message
advances the season and the year. A HUD that predicts its way into the next spring and then gets corrected
is worse than one that sits at まもなく for 200 ms.

That rule is structural, not a discipline to remember: the displayed year and season come from
`clock.year` / `clock.season`, which are authoritative, so **`nationSeasonOfTick` and `nationYearOfTick` are
never called on the current tick client-side.** The one legitimate client-side use is labelling a *past*
tick — `ActiveDirective.issuedAtTick` in the report's 完了した施策 line — where it is a pure function of
history and cannot run ahead of the server.

### 3.1a Which year the player sees

Plan Task 1 fixes this and assigns it here:

> The calendar year shown to the player is `history.currentYear + nationYearOfTick(tick) - 1`, computed at
> the display edge in Task 6, never here.

`clock.year` is already the 1-based elapsed game year, so the display edge only needs `history.currentYear`,
captured once from `welcome` (it never changes mid-game) and held by `createNationHud`:

```
calendarYear = history.currentYear + clock.year - 1
```

The clock bar shows the calendar year with the elapsed year in parentheses — `紀元1043年 夏（第3年）` — because
the calendar year connects the game to the 200-year chronicle the player just read, while the elapsed year is
what the score and the roadmap's "N年時点の首位" option are measured in. Every other surface (report header,
directive panel header, directive issue dates) shows the calendar year only.

At x0 the countdown freezes and switches units: it shows `remainingTicks` and the season-progress fraction,
labelled 一時停止中, with no seconds. Seconds are meaningless when time is not flowing; a frozen "12.4秒" reads
as a bug.

At x8 a season is 3.75 s. The HUD does not pretend otherwise — the countdown bar just moves fast and the
"decide now" emphasis threshold (wall-clock ≤ 5 s remaining) is effectively always on. That is honest: x8 is
for watching, x1–x2 for governing, x0 for thinking. No client-side auto-pause (§6).

### 3.2 One slot always answers "what commits at the next boundary"

The dashboard's 次の決算 slot is never empty. It has exactly three states, and the third is a warning:

| condition | slot reads | source |
|---|---|---|
| `queued !== null` | `祭礼（あなたの発令）` + `[取消]` | `orders.queued` |
| `queued === null && autoPilot` | `伐採地整備（宰相の既定）` | `orders.chancellorChoice` |
| `queued === null && !autoPilot` | `この季は何も実行されません` | derived, emphasised |

The third row is the one that earns the design. Reading `§4.6` of the spec — 「プレイヤーの国も、指示がない季は
宰相が決める（自動運転の明示的なON/OFFを持つ）」 — a queued player order wins even with autopilot on, and
autopilot fills *empty* seasons. So autopilot OFF plus no order means the nation idles, and that must be
visible before the boundary, not discovered in the report afterwards. Assumption to confirm with the
simulation owner: autopilot is "fill the gap", not "the chancellor always decides". If it turns out to be
the latter, the queued slot must show the player's order as *overridden* instead, and the toggle needs a
different label.

Toggle wording follows from that reading: ON = 宰相に任せる, OFF = 指示がなければ何もしない, with the accessible
description spelling out that an order you issue yourself always takes precedence.

### 3.3 Autopilot is a following mode, not a lesser mode

A player who leaves autopilot on is a spectator with a reason to watch. What makes that work:

- **Before**: `chancellorChoice` is shown in the queued slot for the whole season, so the chancellor's
  decision is legible *in advance*, every season, without any LLM.
- **Why**: the directive panel shows the same option list the chancellor scored, with each option's
  `affinity` and the nation's top cultural values named. The chancellor's pick is marked 宰相の推奨 in the
  list. The player can see it chose the highest-affinity affordable option, and can see the deficit term at
  work by comparing against the previous season's report.
- **After**: the season report attributes the directive that committed — あなた or 宰相 — via the queued-id
  bookkeeping from §2.3.
- **Handing control back and forth is one keystroke** (`A`) and needs no other change: autopilot is
  orthogonal to issuing an order. Queue an order with autopilot on and your order commits; the chancellor
  fills the next empty season. There is never a mode to "take over" from.

### 3.4 The directive panel makes the tradeoff legible

One card per `DirectiveOption`. Every `DirectiveKind` is present every season — the server sends blocked
options with reasons rather than omitting them (plan Task 3), which is what makes the panel a stable,
learnable list rather than a shuffling menu.

```
┌ 施策を選ぶ ─────────────── 紀元1043年 夏 · 残り 12.4秒 ───┐
│ ▸ 開墾                        所要 2季     国柄適合 +0.6 │
│   食料 −20  資材 −40  富 0                               │
│   ▓▓▓▓▓▓▓▓░░░  保全・相互扶助に沿う           [発令する] │
│                                                          │
│ ▸ 祭礼                        所要 1季     国柄適合 +0.9 │
│   食料 −10  資材 0   富 −60                  ★宰相の推奨 │
│   ▓▓▓▓▓▓▓▓▓▓▓  信仰・血縁に沿う               [発令する] │
│                                                          │
│ ▸ 鉱山開発                                     発令不可 │
│   丘陵・山岳を領有していません                           │
│                                                          │
│ ▸ 都市育成                                     発令不可 │
│   富が 40 足りません（保有 88 / 必要 128）               │
│                                                          │
│ ▸ 開墾（第二都市）                             発令不可 │
│   同じ対象で実行中です                                   │
└──────────────────────────────────────────────────────────┘
```

Rules:

- **Cost** is the raw `NationStocks` triplet with the shortfall named, not a red tint. `insufficientWealth`
  becomes 富が 40 足りません（保有 88 / 必要 128） — the arithmetic is the server's `blockedReason` plus two
  numbers the client already has (`cost`, `nation.stocks`). Formatting a shortfall is not judging legality.
- **Duration** is 所要 N季 plus its wall-clock equivalent at the current speed on hover/`aria-description`
  (2季 = 60秒 at x1) — because the player's real budget is wall clock, not seasons.
- **Affinity** is a −1..1 signed meter with the nation's matching top cultural values named from
  `Polity.values` (reuse `strongestValues`'s ordering idea from `worldChronicle.ts`). A number alone teaches
  nothing; 保全・相互扶助に沿う teaches the nation's character. Negative affinity is drawn as a *cost*
  (国柄に反する — 安定が下がります), because that is what it does.
- **Blocked** options are focusable with `aria-disabled="true"` and a no-op activation, never
  `disabled` — `disabled` removes them from the tab order and hides exactly the explanation the design
  exists to deliver. The reason is part of the accessible name.
- `taboo` quotes `Polity.taboo` verbatim: 禁忌：「◯◯」。この国はこれを選べません.
- The 宰相の推奨 star is `chancellorChoice`, so the panel doubles as the autopilot explainer.

### 3.5 Keyboard

Extending, not replacing, what `keyboardNavigation.ts` established.

| key | action | scope |
|---|---|---|
| `←↑→↓` | move the cell cursor on the world map | map canvas focused |
| `Enter` | select the nation owning the cursor cell (public panel; own nation → dashboard focus) | map canvas focused |
| `Space` | same as `Enter` (established precedent — see collision note) | map canvas focused |
| `0` `1` `2` `4` `8` | set speed directly | document |
| `P` | toggle pause ↔ last non-zero speed | document |
| `A` | toggle autopilot | document |
| `D` | open/close the directive panel | document |
| `R` | open/close the latest season report | document |
| `C` | open/close the chronicle (existing button gains a key) | document |
| `Escape` | close the topmost open panel, else clear selection | document |

**Space collision, decided:** Space is already "activate the cursor cell" on the canvas
(`handleCanvasKeydown`: `if (event.key === "Enter" || event.key === " ")`), and Space is also the
conventional pause key. Convention loses. Rebinding Space to pause would break the established activation
grammar and would fight every focused button in the DOM panels, which activate on Space by default. Pause
gets `P`, and `0` sets speed 0 — both discoverable from the visible `[⏸][x1][x2][x4][x8]` labels once
they carry key hints. Document-level letter/digit keys are safe because `index.html` contains no text
input; the handler still bails when `event.target` is an editable element, so N3's diplomacy screens do not
have to remember to.

Within panels: `↑↓` move between option cards / report rows, `Enter` activates, `Escape` closes and returns
focus to the opener — the `createWorldChronicle(root, onClose, returnFocus?)` pattern.

Announcements through the existing `#world-status` live region, and only for things that are not already
visible: order accepted or rejected with the reason, autopilot flipped, speed changed, season resolved with
its one-line headline, nation selected. Not the countdown — a live region that re-announces every second is
unusable.

### 3.6 Reconnect

`socket.onclose` reopens and the server re-sends `welcome`. Rules:

- The selected nation comes back from `NationWorldState.playerNationId`; the client does not re-send
  `selectNation` — that would race a server that already knows.
- Queued-order bookkeeping (the set of ids the player ordered) is **dropped, not replayed**. Replaying an
  `issueDirective` after a reconnect could double-order across a boundary. The consequence is honest and
  small: directives issued before the reconnect are attributed to 宰相 in later reports. Say so in the
  announcement: 再接続しました。発令の履歴は失われました。
- The countdown re-derives from the first `clock` after `welcome`; until then it shows 同期中.

### 4.5 The season report: a diff with reasons

`SeasonReport` is `{ year, season, entries: SeasonLedgerEntry[], completedDirectiveIds }`, and each entry is
`{ metric, delta, reason, directiveId }`. The client's job is to group, not to list.

```
┌ 紀元1043年 夏 の決算 ──────────────────────────────────────────┐
│ 人口の消費が食料を24削り、成長が人口を18増やした。            │  ← headline: largest |delta|, both signs
│                                                               │
│ 食料   +12  ▲   基礎生産 +40 · 人口の消費 −24 · 施策の維持 −4 │
│ 資材    −6  ▼   基礎生産 +10 · 施策の支出 −16                 │
│ 富      +3  ▲   交易収入 +9 · 施策の支出 −6                   │
│ 人口   +18  ▲   人口成長 +18                                  │
│ 安定    −3  ▼   国柄との一致 −5 · 安定の自然変動 +2           │
│ 文化     ―      変化なし                                      │
│                                                               │
│ 完了した施策: 開墾（あなたの発令 · 第2年 春 発令）            │
└───────────────────────────────────────────────────────────────┘
```

Design rules:

- **Fixed metric order** — food, materials, wealth, population, stability, culture — never sorted by
  magnitude. A row that moves between seasons cannot be read at a glance; a row that stays put can be read
  peripherally. Unchanged metrics keep their row and read 変化なし.
- **Reasons sorted by |delta| descending** within a metric, so the cause of the movement is leftmost.
- **The headline is one sentence naming at most two reasons**: the largest-magnitude negative and the
  largest-magnitude positive across all metrics. This sentence, and only this sentence, goes to the
  always-on decision strip and the live region. It is the seam where the client's job (文章化, per spec §4.3)
  is small and honest — templated from `metricLabel` × `ledgerReasonLabel` × the number, with no prose
  generation and no LLM.
- **`famine` is escalated**: any `famine` entry pins the report open (it does not require the player to
  press `R`) and colours the strip with the existing `HUD_ALERT_COLOR` family. It is the only entry with
  that privilege.
- **Completed directives** are named via `directiveKindLabel`, attributed あなたの発令 / 宰相の決定 from the
  queued-id set, with the issue date reconstructed from `ActiveDirective.issuedAtTick` observed before
  completion (the client must retain the last-seen `activeDirectives` to do this; that is bookkeeping, not
  simulation).
- **Entries whose sum is zero still show their reasons.** `+40 / −40` is a story; a blank row is not.
  Task 4 asserts the ledger sums to the observed delta, so the client can trust the arithmetic and never
  needs to recompute or reconcile.

### 4.7 Scale traversal: what persists, what changes, what is meaningless

The persistence contract is one rule: **the nation HUD reads `NationWorldState` / `orders` and never
`WorldState`.** The scene beneath it is a swappable child. Given that, `main.ts` can mount and unmount the
Pixi local scene without the HUD noticing.

`bfebc09` adopted the local map as spec §7.4 while this was being written, and it fits: 「往来は視点の移動で
あり、モードではない」, 「ローカルマップにいる間も世界は進み続ける。時間が止まるのは速度x0を選んだときだけである」, and the initial
local map is a read-only view 「国家状態・都市・seedから決定論的に導出される」. Two consequences for the HUD.

First, if that derivation happens client-side, the local scene will synthesize a `WorldState`-shaped object
to feed the frozen renderers. **That synthesized object is the local scene's private business and must never
reach a nation view model** — otherwise the rule above is satisfied on paper and violated in practice.

Second, §7.4's reuse list is 「`mapLayer`・`structureLayer`・`agentLayer`・`terrainDecor`・`shadow`・`trailLayer`」 —
`hudLayer` and `tickerLayer` are absent from it. That confirms the call in §4.4: the resident Pixi HUD and
ticker leave the live path permanently at both scales, and the DOM clock bar plus decision strip replace them
everywhere.

| | world scale | local (capital interior) scale |
|---|---|---|
| Clock bar, countdown, speed, autopilot | identical | identical — the clock is national, and the season boundary commits whether or not you are standing in your own street |
| Commit slot, directive panel | identical | identical — directives are national |
| Season report, decision strip | identical | identical |
| Prosperity ranking | identical | identical (public numbers stay public) |
| Own dashboard | identical | identical, plus "you are in ◯◯" breadcrumb |
| Scene | `renderWorldMapCanvas` + `renderNationMapOverlay` | Pixi resident scene |
| Cell cursor | 96×64 cells, `Enter` selects a nation | tiles, `Enter` inspects a resident/facility (frozen resolvers) |
| Territory paint, trade routes, capital rings | meaningful | meaningless — one nation, one city |
| `foodDays`, `woodForecast`, needs meters, thought bubbles, death markers, trail wear | meaningless | meaningful (frozen resident HUD) |

The hazard is `main.ts`'s single `state: WorldState | null` plus one shared dirty-flag set. If the nation HUD
is wired into that, mounting the local scene will re-render nation panels and vice versa. Keeping
`createNationHud` as the only nation entry point, with its own internal invalidation, is what makes the
traversal cheap.

### 4.8 Where the countdown gets its render loop

At x0 nothing needs redrawing, so a `requestAnimationFrame` loop that repaints the countdown 60×/s while
paused is waste, and Pixi's `app.ticker` should not be the nation HUD's clock (it belongs to the scene that
may be unmounted). `createNationHud` exposes `tick(now)` and `main.ts` calls it from a
`requestAnimationFrame` loop that the HUD itself short-circuits: the countdown text re-renders only when its
displayed value changes (one decimal at 10 Hz), and not at all while `speed === 0`.

### 4.9 The two duplication decisions, stated rather than smoothed over

**`moveTileCursor`.** Preferred: move `moveTileCursor` + `ARROW_DELTAS` + `clamp` + `isArrowKey` into
`ui/gridCursor.ts` and have `keyboardNavigation.ts` re-export `moveTileCursor`. `keyboardNavigation.test.ts`
imports from `../src/ui/keyboardNavigation.js`, so it stays green with no test edit — verified by reading its
import block. Importing it in place instead would drag `render/mapLayer.js` (and therefore Pixi and the
sprite sheet) into the nation bundle, because `keyboardNavigation.ts:3` is
`import { TILE_SIZE } from "../render/mapLayer.js"`. Fallback if the supervisor treats any edit to a frozen
module as off-limits: duplicate the 14 lines in `gridCursor.ts` and say why in the commit body.

**Season labels.** `survivalViewModel.ts:67` already has `SEASON_LABELS: Record<Season, string>` with the
same `SEASONS` union, and `hudLayer.ts:18` has a parallel `SEASON_COLORS`. The nation HUD gets a **second**
label table in `nationText.ts` rather than importing the first, because `survivalViewModel.ts` imports
`WorldState`, `DAYS_PER_SEASON`, `foodDaysRemaining`, `WOOD_BURN_PER_AGENT_PER_DAY` — importing it would
couple the nation layer to the frozen resident contracts, which spec §5 forbids. Accepted duplication: four
string literals, with a comment naming the original. Deduplicating properly means promoting the table to
`packages/shared`, which is a shared-package change this design does not need.

## 6. What I left out and why

- **A HUD design that works without the §2.3 `orders` message.** It would mean either the client judging
  directive legality (forbidden by §8.4) or optimistic rendering with a wall-clock timeout that cannot tell a
  rejection from a slow server and misleads the player at exactly the speed — x0 — the spec calls a
  legitimate way to play. The gap is named instead.
- **Auto-pause at boundaries, slow-motion near the boundary, or any client-driven speed change.** The player
  owns the speed control; a HUD that takes it is a HUD that lies about who is in charge.
- **An LLM-authored season narration, ruler portrait, or declaration text.** Everything in this design reads
  from `SeasonLedgerEntry`, `DirectiveOption` and `ProsperityScore`. N4 can add the 元首's voice as an extra
  line; nothing here degrades without it.
- **Score-history graphs, replay scrubbing, victory screens.** N6.
- **Diplomacy surfaces.** N3. Note only that the ranking rows are the natural anchor for future relation
  state, so the row component should not be over-fitted to five numbers.
- **A settings screen, layout customisation, or panel docking.** No requirement asks for it, and every
  panel here is either always-on or one key away.
- **Porting the resident info-bubble gesture stack.** §4.6.

1. **§2.1 blocks C2.** Without `options` on the wire there is no directive panel and therefore no game.
   Highest-priority item; needs a decision before C2, ideally during C1.
2. **§2.2 makes x0 a dead end.** Without an acknowledgement path, pausing and issuing an order is
   indistinguishable from pausing and being ignored. Fixed by the same message.
3. **§2.4 blocks C4.** If Task 4 lands raw components, the breakdown either cannot be drawn or forces the
   client to duplicate the normalisation. Cheap to settle now, expensive after `prosperity.ts` has tests.
4. **Rival state is on the wire (§2.5).** No fix inside the client. Becomes a real problem in N3.
5. **Directive attribution is client-side bookkeeping.** It is exact while the session lasts and lost on
   reconnect, so post-reconnect reports over-credit the chancellor. The clean fix is a `decidedBy` field on
   `ActiveDirective`, which `nation.ts` freezes; registered as an N2 request, not done here.
6. **Two render stacks in the tree.** Canvas 2D at nation scale, Pixi at local scale. They never render
   simultaneously, but the top-level `await Assets.load` means N1 pays for Pixi assets it does not draw
   until that is deferred.
7. **`main.ts` complexity.** Biome's cognitive-complexity ≤ 10 gate will reject a naive wiring. The
   single-entry-point `createNationHud` is not stylistic preference; it is what makes the slice pass its own
   gate.
8. **Report fatigue at 30-second seasons.** Two reports a minute, forever. Mitigated by making the strip the
   default and the panel opt-in, and by giving only `famine` the right to interrupt. If playtesting shows
   the strip is still noise, the next lever is to suppress the headline when every metric moved less than a
   threshold. That threshold is a game constant, and `bfebc09` bars the client worker from editing
   `shared/constants.ts` — so it is a stop-and-report, not a client-side tweak.
9. **Clock prediction and long GC pauses.** The clamp keeps the display honest, but a stalled tab resumes
   with a stale countdown for up to one `CLOCK_BROADCAST_MS`. Acceptable; the alternative is showing 同期中
   for a second every time the tab is backgrounded.
10. **Autopilot semantics (§3.2) are an inference from spec §4.6, not a stated contract.** If a queued player
    order does *not* override autopilot, the commit slot and the toggle label are both wrong. One question
    to the simulation owner settles it; the rest of the design is unaffected.
