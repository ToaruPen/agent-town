# 農耕 — 食料に季節を与える

## 1. 何を直すのか

制度が生まれない。5シードのうち成立するのは1つで、それも tick 34,500 前後、実時間にして小一時間かかる。多くのセッションで、プレイヤーは合議体も施設も一度も見ない。

原因を測った。制度の引き金は `foodDaysRemaining(world)` が `INSTITUTION_FOOD_PRESSURE_DAYS`（4日）を下回ることで、支持は `COLLECTIVE_FORMATION_TICKS`（2400tick）**連続**して初めて形になる。ところが集落の食料残日数は 4.8 から 5.5 のあたりで平らに張り付く。閾値のすぐ上である。谷は来るが、浅くて短い。

地図の食料を減らせば解決するように見えて、しない。8シード×36,000tick で在庫を8分の1まで落としても、集積所の最終食料は82に対して79、残日数は4.9に対して4.8だった。住民は地図にある量ではなく**自分の目標値**に向かって採集し、足りたら止める。平衡は供給ではなく需要が決めている。

効いたのは在庫ではなく**流量**だった。ベリーの日次再生量を676/日から37/日まで落とすと制度は8シード中4つで成立し、19/日まで落とせば8つ全部で成立する。ただし19/日では移民が止まり、人口は初期の3人から動かなくなる。集落が凍りつく。

ここに設計上の分岐がある。流量を絞れば制度は生まれるが村は育たない。流量を保てば村は育つが制度は生まれない。**一定の細い流れである限り、この二択から出られない。**

出口は量ではなく形にある。

## 2. 農耕が変えるもの

農耕は食料を秋の一括に変える。1年は8日（`DAYS_PER_SEASON` が2、四季で8日）。秋に穫れた分で冬と春を越し、次の収穫までつなぐ。すると残日数は平らでなくなる。収穫直後に山が来て、翌年の収穫前に必ず谷が来る。

この谷は連続している。だから2400tickの支持が積める。

しかも谷は毎年同じ時期に来る。プレイヤーにとって「なぜ今食べ物がないのか」が分かる欠乏になる。理由の分からない欠乏は不具合に見え、理由の分かる欠乏は物語に見える。制度が生まれる瞬間に、生まれる理由が画面に映っていることが重要なのであって、制度の成立率だけを上げても意味がない。

副次的な効果がひとつある。ブラウザ検証で4項目が確認不能になった。18,699tick 走らせても伐採済みの森が現れず、施設も制度も死者も出なかったからである。集落が平穏すぎて見るべきものが起きない。欠乏は、見るべきものを起こす。

## 3. 素材

Kenney の Tiny Farm パック（CC0、16×16、130タイル）をリポジトリに加える。既存の tiny-town・tiny-dungeon と同じ作者・同じ系列で、画風の差はない。

このパックには作物の生育段階が揃っている。小麦なら、芽・生長・実り・収穫物・種袋・木箱まで一貫している。畑が「播いた」「育っている」「実った」のどれなのかを、文字ではなく絵で言える。畝の入った耕地タイルも乾湿と角つきで揃う。

家畜（羊・牛・鶏）と納屋も入っているが、本仕様では使わない。牧畜は食料に**細く一定の流れ**を足す方向であり、農耕がせっかく作った谷を埋めてしまう。農耕の谷の深さを実測してから、別仕様で位置づけを決める。

野生動物と魚はこのパックにも他の既存パックにもない。狩猟と漁労は本仕様の範囲外とする。入れるなら罠と籱——置いて後日回収する形——になるが、それは別の話である。

## 4. 設計

### 4.1 畑は建物である

畑を `Building` の第三の種として加える。既存の union は `House | Facility` で、`isHouse` と `isFacility` の述語がある。ここに `Field` を足すと、用地選定・建設進捗・描画・深度整列・情報吹き出しがそのまま使える。新しい層を作らない。

畑は1タイルを占める。作物タイルは本来もっと広い区画のために描かれているが、16px の実寸では1タイルの畑でも作物として読める。集落が育って畑が増えれば、隣り合った畑が自然に一枚の耕地に見える。最初から複数タイルの区画を導入するより、状態が単純で、`siteSelection` にも手を入れずに済む。

### 4.2 状態は季節が動かす

畑は4つの状態を持つ。

| 状態 | 見た目 | 遷移 |
| --- | --- | --- |
| `fallow` | 畝だけの耕地 | 建設完了時、および収穫後 |
| `sown` | 芽 | 春に播種の作業を終えたとき |
| `growing` | 生長中の株 | 夏の始まりに自動で |
| `ripe` | 実った作物 | 秋の始まりに自動で |

生長はティック単位のタイマーではなく季節の境界で進める。`seasonOfTick` は既に純関数として `@agent-town/shared` にあり、サーバーが配信する `world.tick` から決まる。タイマーを持たせないので、状態はティック数に依存せず、シードが同じなら同じ絵になる。

冬に `sown` や `growing` のまま残った畑は `fallow` に戻る。凍害である。播き遅れが翌年の欠乏として返ってくる。

### 4.3 作業

3つのタスクを足す。いずれも既存の `AgentTask` の union に加わる。

- **開墾** — 畑を建てる。既存の建設と同じく進捗を積む。木材は要らない。土地と労力だけを使う。
- **播種** — 春のあいだだけ。`fallow` の畑を `sown` にする。
- **収穫** — 秋のあいだだけ。`ripe` の畑から `FIELD_YIELD` の食料を集積所に入れ、畑を `fallow` に戻す。

季節の窓を外れた作業は計画されない。春に播きそこねた畑はその年は実らない。これが農耕を賭けにする。

### 4.4 planner

`FakePlanner` の優先順位に畑を挟む。現在は 緊急（空腹など）→ 住居 → 資源 の順で、ここに 緊急 → 住居 → **畑** → 資源 と入れる。

住居より下に置くのは、屋根のない集落が畑を耕す絵が不自然だからである。資源より上に置くのは、播種と収穫が季節の窓を持つためで、窓の中では他の作業より優先されなければ機会を逃す。

畑を何枚建てるかは人口から決める。住居が `HOUSE_CAPACITY` から必要数を出しているのと同じ形にする。

### 4.5 均衡

ベリーの再生流量を落とす。測定では 37/日 が、制度が8シード中4つで成立しつつ人口も 3.8 を保つ点だった。ただしこれは農耕がない前提の数字である。農耕が秋の山を足すぶん、ベリーはもう少し絞れる余地がある。

流量は `食料タイル数 × min(BERRY_REGROWTH_PER_DAY, タイルの初期量)` で決まる。現在は 169タイル × 4 = 676/日。`FOOD_TILE_CHANCE` を下げてタイル数を減らすか、`BERRY_REGROWTH_PER_DAY` を下げるか、両方かで到達できる。

タイル数を減らす側を選ぶ。現在の169タイルは3072タイル中の5.5%が地図全体に均一に散っていて、視覚的にはノイズに近い。数十箇所まで減れば、ベリーの藪は「歩いて行く価値のある場所」になり、そこへ向かう小道が意味を持つ。V3 で小道を描き直した効果が、ここで初めて生きる。

畑の収量は、集落が冬と春を越せる量から逆算する。住民1人が1日に約4.2の食料を消費する（`HUNGER_DECAY_PER_DAY` 50 を `HUNGER_PER_MEAL` 60 で割り、`FOOD_PER_MEAL` 5 を掛ける）。収穫から次の収穫まで6日あるので、1人あたり約25の食料が要る。畑1枚がおよそ1人を養う量を目安とし、実測で詰める。

**具体的な定数は実測で決める。** 上の数字は出発点であって結論ではない。8シード×36,000tick の掃引を回し、制度の成立率・人口・餓死数・収穫前の谷の深さを見て確定させる。

### 4.6 死は起こりうるが、起こりにくい

これまで餓死は一度も観測されていない。欠乏を導入する以上、死は起こりうるようになる。それでよい。ただし**毎年何人か死ぬ**のは行き過ぎで、集落が消えるのは論外である。

掃引の合格条件に「全滅シードがゼロ」を入れる。餓死がまれに起こる程度に収める。死は物語の句読点であって、平均値であってはならない。

## 5. 検証

- 8シード×36,000tick の掃引で、制度の成立率、最終人口、餓死数、全滅数、収穫前の残日数の最小値を測る
- 同じシードで2回走らせて世界が深く一致する（既存の決定性の条件）
- `sim/` に `Date.now()` と `Math.random()` を入れない
- 新しいタイルはすべて `SPRITE_PATHS` に登録し、何が描かれているかのコメントを添える
- 畑の状態遷移は季節境界でのみ起き、ティック数に依存しない

## 6. 範囲外

牧畜、狩猟、漁労。複数タイルの区画。作物の種類の選択（小麦のみとする）。灌漑。土壌の肥沃度。輪作。

これらはどれも自然な続きだが、本仕様は「食料に季節を与える」という一点に絞る。谷が実際にどれだけ深くなるかを測ってからでなければ、次に何を足すべきかは決められない。
