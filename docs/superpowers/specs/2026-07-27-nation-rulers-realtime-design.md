# 国家統治リアルタイム競争 設計仕様書

日付: 2026-07-27
ステータス: オーナー承認待ち（方針4点は2026-07-27に決定済み）

## 1. 目的

agent-town を、**住民の暮らしを神の視点から観察するコロニーシム**から、**エージェントとプレイヤーがそれぞれ一国を統治し、リアルタイムで繁栄を競うゲーム**へ転換する。

エージェントは世界に生きる住民ではない。世界に既に存在する国家の統治者である。プレイヤーもまた統治者のひとりとして同じ盤上に立つ。

> 200年の世界史が国家と国柄を作る
>
> → 現存する国家がプレイ可能勢力になる
>
> → プレイヤーが1国を選び、残りをエージェントが統治する
>
> → 各国が季ごとに施策を決め、経済・人口・領土が動く
>
> → 繁栄度の順位がリアルタイムで入れ替わる

## 2. 既存仕様との関係

本仕様は `2026-07-23-emergent-fantasy-society-design.md` の**上位ゲームレイヤーを置き換える**。矛盾する場合は次の点で本仕様を優先する。

| 論点 | 旧仕様 | 本仕様 |
|---|---|---|
| エージェントの役割 | 入植地の住民 | 国家の統治者 |
| プレイヤーの立場 | 観察者・間接介入者 | 統治者のひとり（AI国家と対等） |
| シミュレーション単位 | 住民個体（10人規模） | 国家（3〜5国） |
| 進行 | 常時進行の観察 | 常時進行＋速度調整・一時停止 |
| ゴール | 勝敗なし | 繁栄度スコアによる競争 |
| 主舞台 | 64×48 ローカル入植地 | 96×64 世界地図 |

次の点は旧仕様から**そのまま維持する**。これらは本仕様の土台であり、再設計しない。

- 世界史生成（200年・4国家・因果付きイベント）と `WorldHistory` 契約
- 世界地図生成（領土、都市、交易路、戦争由来の国境変化）と `WorldMap` 契約
- 国柄（`Polity.values` の文化価値重みと、その変化根拠イベント）
- 決定論の原則: `sim/` は seed 付き乱数のみ、時刻APIとI/Oを持たない
- LLM境界: LLMは列挙された候補から選ぶだけで、状態を直接生成しない
- 複数プロバイダールーティング契約（`2026-07-22-multi-provider-llm-routing-design.md`）

## 3. 体験の柱

### 3.1 世界史があなたの国を作る

新規ゲームは今までどおり200年の世界史生成から始まる。違うのは、その結果が「観察対象の背景」ではなく**あなたが引き継ぐ国の初期条件**になることである。

- 長い包囲を生き延びた国は備蓄と防壁を重んじ、開幕から食料備蓄が厚い
- 交易路で栄えた国は富の初期値と交易収入が高い
- 魔術災害を経験した国は禁忌を持ち、特定の施策が取れない

国柄は飾りではなく、**施策の効率と宰相AIの選好に直接効く数値**である。

### 3.2 統治者は候補から選ぶ

統治者（プレイヤー、エージェントのどちらも）は自由記述で世界を書き換えない。シミュレーションが毎季、その国が実行可能な**施策候補**を列挙し、統治者はそこから選ぶ。

これにより、
- プレイヤーとエージェントの権限が厳密に対等になる
- LLMが不正な状態変更を起こせない
- LLMを止めても同じゲームが最後まで成立する

### 3.3 リアルタイムだが取り残されない

世界は常に進む。プレイヤーが指示を出さなかった季は、その国の**宰相（決定論的AI）**が国柄に沿って自動的に決める。放置しても国は滅びないが、良い統治者には及ばない。

速度は x1 / x2 / x4 / x8 と一時停止から選べる。速度は実時間あたりのティック消費量だけを変え、**シミュレーション結果には影響しない**。同じ seed で同じ入力なら、どの速度で観戦しても tick N の状態は一致する。

### 3.4 繁栄度で競う

各国は毎季**繁栄度スコア**を持つ。人口・生産・富・安定・文化の加重合成で、順位はリアルタイムで入れ替わる。

スコアは不透明な総合値にしない。内訳と、前季からの変動理由（何が増え、何が失われたか）を必ず参照できるようにする。

### 3.5 プレイヤーとエージェントは対等

同じ施策候補、同じコスト、同じ情報公開範囲。エージェントが見られない自国の内情をプレイヤーだけが見られる、という非対称は作らない（逆も同様）。他国について見えるのは公開情報のみとする。

## 4. ゲームの構造

### 4.1 時間

| 単位 | 値 | 実時間 (x1) |
|---|---|---|
| tick | 既存の `TICK_RATE = 10` を維持 | 0.1秒 |
| 季 | `NATION_TICKS_PER_SEASON = 300` | 30秒 |
| 年 | 4季 = `NATION_TICKS_PER_YEAR = 1200` | 2分 |

**季の境界がすべての決定境界**である。施策の発行はいつでもできるが、効果は次の季解決から現れる。

住民スケールの既存定数（`TICKS_PER_DAY`、`DAYS_PER_SEASON` など）は改名も削除もしない。国家スケールの定数を新しい名前で追加する。

### 4.2 国家状態

国家は世界史が生成した `Polity` に対応する。`Polity` は不変の来歴（名前、色、国柄、創設神話、禁忌）を持ち、`NationState` が可変のライブ状態を持つ。両者を混ぜない。

`NationState` が最低限持つもの:

- 統治者種別（`player` / `agent`）
- 備蓄（食料、資材、富）
- 都市ごとの人口と開発度
- 領土セル数
- 総人口
- 安定度（0〜100）
- 実行中の施策
- 繁栄度スコアと内訳
- 直近の季報告（`SeasonReport`）

### 4.3 季解決の順序

季ごとに、すべての国について**固定順序**で解決する。国のID昇順で処理し、処理順が結果を変えないようにする（同季内の相互作用は解決前のスナップショットを参照する）。

1. 施策の適用（コスト徴収、効果反映、残季数の減算）
2. 生産（食料、資材、富）
3. 消費（人口の食料消費、施策の維持費）
4. 人口変動（成長 / 飢餓による減少）
5. 安定度の更新（食料充足、施策と国柄の一致、危機）
6. 領土・都市の更新（拡張、放棄）
7. 繁栄度スコアの再計算
8. `SeasonReport` の生成（各変動に理由コードを付ける）

`SeasonReport` は説明用の文章ではなく**構造化された台帳**とする。文章化はクライアントとLLMの仕事である。

### 4.4 繁栄度スコア

```
total = 1000 × Σ ( weight_i × normalize_i(component_i) )
```

初期の構成要素と重み（`packages/shared/src/constants.ts` に置き、調整可能）:

| 構成要素 | 重み | 意味 |
|---|---|---|
| 人口 | 0.30 | 総人口 |
| 生産 | 0.25 | 季あたりの食料＋資材産出 |
| 富 | 0.20 | 蓄積された富 |
| 安定 | 0.15 | 安定度 |
| 文化 | 0.10 | 文化施設・祭礼による蓄積 |

正規化は**固定の基準値**で行い、他国との相対値では行わない。他国が滅んだだけで自国のスコアが上がる、という挙動を避けるためである。順位は正規化後のスコアを比較して別途決める。

勝敗の扱い: 既定は無期限進行とし、スコアと順位の推移を見せる。オプションで「N年時点の首位」を決着とできるようにするが、最初の縦切りには含めない。

### 4.5 施策（Directive）

施策は列挙値で定義し、それぞれが次を持つ。

- 前提条件（備蓄、領土、都市、既存制度、国柄の禁忌）
- コスト（食料、資材、富）
- 所要季数
- 効果（決定論的な状態変化）
- 国柄との適合度（安定度の増減に効く）

最初の縦切りで実装する施策は経済と内政に限定する。

| 施策 | 主効果 |
|---|---|
| 開墾 | 食料生産の恒久増加 |
| 伐採地整備 | 資材生産の恒久増加 |
| 鉱山開発 | 富の生産増加（丘陵・山岳が必要） |
| 都市育成 | 都市の人口上限と開発度の上昇 |
| 備蓄奨励 | 食料備蓄の効率上昇、消費の平準化 |
| 祭礼 | 安定度と文化の上昇、富を消費 |

外交・軍事・拡張は後続スライスで追加する（4.8）。

### 4.6 宰相（決定論的統治者）

すべての国は宰相を持つ。宰相は純粋関数で、次を入力に施策候補へ点数を付け、最高点を選ぶ。

- 現在の `NationState`
- 施策候補一覧
- `Polity.values`（国柄の文化価値重み）
- 直近の `SeasonReport`（不足している要素を優先する）

宰相はLLMを一切使わない。**LLMが完全に停止していても、ゲームは開幕から決着までひとりで走り切る**。これは受け入れ条件であり、努力目標ではない。

プレイヤーの国も、指示がない季は宰相が決める（自動運転の明示的なON/OFFを持つ）。

### 4.7 元首（LLM統治者）

エージェント国家には元首を割り当てられる。元首は宰相を**置き換えるのではなく、節目で上書きする**。

呼び出す節目:

- 年の初め（その国の年次方針）
- 危機の発生（飢饉、疫病、侵攻、内乱）
- 外交提案の受諾・拒否
- 重大な施策の完成（命名と宣言文）

呼び出さない場面:

- 毎季の通常判断（宰相が処理する）
- 数値計算、順位計算、コスト判定
- 施策候補の生成

元首への入力は、公開可能な状態要約と**施策候補のIDリスト**のみ。出力は「選んだ候補ID」と「短い理由」の厳格なスキーマで検証する。未知IDや前提を満たさない選択は破棄し、宰相の判断へフォールバックする。

既定プロバイダーはCodex、明示割当時のみClaude（既存のルーティング契約を維持）。呼び出しは既存の `LLM_MAX_CALLS_PER_HOUR` 予算内に収め、超過時は緊急度の高い国から順に配分する。

### 4.8 外交と戦争（後続スライスの骨子）

最初の縦切りには含めないが、契約設計を先に固めておく。

- 国家間の提案は**構造化メッセージ**（交易協定、停戦、同盟、宣戦、貢納）とし、条項は列挙値と数値で表す
- LLMは提案の文言と、受諾/拒否の選好表明だけを担う
- 戦争は領土セルの所有権変更として解決し、変更には必ず原因イベントIDを残す（既存 `WorldBorderChange` と同じ形式でライブ拡張する）
- 関係値は世界史が残した初期関係から始まる

## 5. 既存資産の扱い

| 資産 | 扱い |
|---|---|
| `sim/historyGen.ts`、`sim/worldMapGen.ts` | **そのまま流用**。国家ゲームの初期世界生成器になる |
| `shared/history.ts`、`shared/worldMap.ts` | **契約維持**。フィールド追加も当面行わない |
| クライアントの世界地図・年代記・国柄カード | **流用**。領土のライブ更新を追加する |
| `sim/engine.ts`、`executor.ts`、`astar.ts`、`fakePlanner.ts` | **凍結**。ライブループから外すがモジュールとテストは残す。将来の都市内部ビューの素材として保持する |
| `sim/society.ts`、`foodAnxiety.ts` | **凍結**。国家スケールの制度モデルは別モジュールとして作り、住民スケールの実装は流用しない |
| `llm/` 一式（ランナー、ルーティング、スキーマ、予算） | **流用**。プロンプトと出力スキーマを統治者用に差し替える |
| クライアントの住民描画層（agentLayer など） | 画面から外すがモジュールとテストは残す |

凍結対象のテストは削除も無効化もしない。純粋モジュールとして通り続けることを維持条件とする。

## 6. LLM境界と予算

1. LLMは**候補選択と文章生成のみ**。座標、資源量、領土、イベントを新設できない。
2. 出力は既知IDと列挙値の厳格スキーマで検証し、不正なら破棄して宰相判断へ落とす。
3. CIは実バイナリ（`claude` / `codex`）を絶対に起動しない。
4. LLM停止時に完走できることを、毎スライスの受け入れ条件に含める。

## 7. 可視化と操作

### 7.1 常時表示

- 世界地図（既存）に、領土・都市規模・進行中の建設がライブ反映される
- 繁栄度の順位表（全国、公開情報のみ）
- 自国パネル: 備蓄、人口、安定度、実行中の施策、次の季までの残り
- 速度コントロール（一時停止 / x1 / x2 / x4 / x8）と現在の年・季

### 7.2 選択時に開く

- 施策の発行画面（候補一覧、コスト、所要季数、国柄との適合、前提を満たさない候補は理由付きで不可表示）
- 季報告: 前季に何がどれだけ増減し、その理由は何か
- 国柄カード（既存）と、その国の公開状態
- 年代記（既存）に、ライブで起きた重大事件が追記される

### 7.3 操作の原則

プレイヤーの操作は施策発行・速度変更・自動運転の切替に限る。地形の直接編集、資源の直接付与、他国の内政干渉は行えない。

## 8. 実装境界

### 8.1 shared

- `nation.ts`: `NationState`、`Directive`、`SeasonReport`、`ProsperityScore` などライブ国家契約
- `constants.ts`: 国家スケールの時間、経済係数、スコア重み、速度倍率
- `protocol.ts`: 国家スナップショットの配信と、クライアントからの施策発行・速度変更

### 8.2 server/sim/nation/

- `bootstrap.ts`: `WorldHistory` から初期 `NationState[]` を導出（決定論的）
- `directives.ts`: 施策候補の列挙、前提判定、コスト、効果
- `chancellor.ts`: 国柄重み付きの決定論的選択
- `season.ts`: 季解決パイプラインと `SeasonReport`
- `prosperity.ts`: スコア計算
- `engine.ts`: tick ループと季境界の検出

すべて純粋・決定論的。`net/`、`llm/`、時刻API、I/O を参照しない。

### 8.3 server orchestration

- 季境界で宰相の決定を適用
- 節目でのみLLM元首へ問い合わせ、検証済みの選択をシミュレーションへ渡す
- 速度と一時停止はループの実時間ペーシングだけを変える

### 8.4 client

- 国家ダッシュボード、順位表、施策発行、速度コントロール、季報告
- 世界地図の領土ライブ更新
- 権威状態の描画のみ。スコア計算も施策の可否判定もクライアントで行わない

## 9. テスト戦略

すべて Red → Green → Refactor。

1. 初期化再現性: 同一 seed で同一の初期 `NationState[]`、別 seed で有意な差
2. 国柄継承: 世界史の人口効果・文化効果が初期備蓄と生産係数へ反映される
3. 季解決の決定論: 同一入力・同一施策列で同一の `SeasonReport`
4. 処理順不変性: 国のIDソート順を変えても同季の結果が変わらない
5. 施策の前提: 前提を満たさない施策は候補に現れず、適用もされない
6. コスト整合: 支払えない施策は発行できず、備蓄が負にならない
7. スコア: 構成要素の増減が期待どおりスコアと順位へ効き、他国の消滅で自国スコアが動かない
8. 宰相: 国柄が異なれば同じ状況で異なる施策を選び、選択は決定論的
9. 速度不変性: x1 と x8 と一時停止をまたいでも tick N の状態が一致する
10. LLM境界: LLM無効で開幕から複数年を完走する。不正IDや前提違反の選択は破棄され宰相へ落ちる
11. 通信: welcome が完全な初期状態を1回だけ送り、update が差分だけを送る
12. UI: 順位表、施策発行、季報告、速度コントロールをブラウザテストで確認する

## 10. 最初の縦切り（N1: Living Nations）の受け入れ条件

- `just check` と `just test` が通る
- ブラウザを開くと、世界史生成で残った現存国家（3〜5国）がライブ状態で表示される
- プレイヤーは開幕時に1国を選べる
- 30秒ごとに季が解決し、人口・備蓄・生産・安定度・スコアが動く
- 繁栄度の順位表がリアルタイムで入れ替わる
- プレイヤーは施策を発行でき、次の季報告にその効果と理由が現れる
- 指示を出さない国（AI国家、および自動運転中の自国）は宰相が国柄に沿って施策を選ぶ
- 一時停止と速度変更が効き、速度を変えても tick N の状態が一致する
- LLMを一切起動せずに10年以上を完走する
- 同じ seed の2回実行で、同じ tick における全国家状態が一致する

## 11. 採用しない案

### 全国家を毎季LLMで動かす

3〜5国 × 年4季 × 常時進行では、費用も待ち時間も再現性も破綻する。宰相が常時統治し、LLMは節目だけを担う。

### LLMに自由記述で国を操作させる

「城を建てた」と書けば建つ設計は、検証も対等性も成立しない。候補選択に限定する。

### プレイヤーだけ特権を持つ非対称設計

観察と介入は前作の柱だったが、本作の柱は競争である。プレイヤーが神の力を持つと、順位に意味がなくなる。

### 住民個体シミュレーションの同時実行

表現は豊かだが、国家スケールの意思決定と両立させると設計難度と計算量が跳ね上がる。都市内部ビューとして後日再導入する余地だけ残す。
