# V3 集落が読める見た目 設計仕様書

日付: 2026-07-27
ステータス: 提案

## 1. 目的

S5までで、住民は制度を立ち上げ、施設を建て、地面に小道を残すようになった。因果は動いている。ところが地図を見ても、それがほとんど見えない。

現在の描画には264枚のタイルのうち12枚しか使われていない。草原と森は同じ草タイルで塗られ、木を伐り尽くした森は草原と見分けがつかない。岩場は土タイルで描かれるが、そこは通れない。家は赤い切妻屋根が一枚、地面に浮いている。中央の集積所は、実際には蜂の巣のタイルである（`SPRITE_ASSETS.stockpile` のコメントは「golden supply chest」と書いてあるが、tile_0094 が描いているのは蜂の巣だ）。

つまり、盤面の情報量が中身に追いついていない。

V3は新しいゲームシステムを足さない。すでに世界が持っている状態を、目で読める形に描き直す。

## 2. スコープ

### 2.1 実装対象

- 地形の描き分け（草原・森・岩場・水面）と、通行可否が見て分かること
- 建物を屋根＋壁＋扉の複数タイルで組み、家と三施設を区別すること
- 小道を「道」として描くこと（現在は角丸の茶色い棒が並ぶ）
- 季節による地図の変化（樹種の入れ替えと地面の色調）
- 住民の同一性（見た目が死亡で入れ替わらないこと）と、運搬物の種類表示
- 接地感のための影
- タイル間の移動を跳躍でなく歩行として見せること

### 2.2 今回は実装しないもの

- 新しいシミュレーション状態、新しいプロトコルフィールド
- 外部からの素材ダウンロード、新規依存パッケージ
- 昼夜サイクル（住民は眠らないため、暗い画面で働く姿が嘘になる）
- タイルアニメーション、パーティクル、効果音
- 既存のUI（観察パネル、ティッカー、HUD、世界地図）の再設計

## 3. 現状の描画が落としている情報

| 世界の状態 | 現在の描画 | 読み取れるか |
| --- | --- | --- |

| `terrain: "rock"`（通行不可） | 土タイル tile_0025/0040 | 歩ける地面に見える |
| `terrain: "water"`（通行不可） | 単色の矩形 `0x3b6ea5` | 穴が空いたように見える |

住民のスプライトは `agentSpritePath(index)` が `world.agents` の配列位置から選ぶ。誰かが餓死して配列から外れると、それ以降の住民の見た目がひとつずつずれる。名前と顔の対応が壊れる。

## 4. 描画方針

### 4.1 通れない土地は通れないように描く

岩場は土タイルの色を石の側へ寄せ、その上に岩塊を散らす。水面は単色をやめ、深部・浅瀬・波の三段で塗る。陸に接する辺の内側だけを浅瀬色にすれば、輪郭が汀線として読める。

森は草タイルに緑を薄く重ね、木を伐った跡地には下草（tile_0029 のきのこ、tile_0017 の若芽）を置く。伐採後も森は森として残り、資源が戻る土地であることが分かる。

食料資源の目印は tile_0002 から tile_0017 の若芽に替える。tile_0002 は花が散った草地そのものを描いたタイルで、地面の一部として沈む。木が地面から立ち上がって見えるのに対し、食料だけが模様として扱われている。輪郭を持つ若芽なら、採れる物として立つ。

花のタイルを草原の装飾に回す案もあるが、資源の目印と混ざる。装飾に使うなら密度を資源より十分に下げ、小道の上には置かない。

### 4.2 建物は屋根と壁で組む

Kenney Tiny Town の建物素材は、屋根タイルの下に壁タイルと扉タイルを積む前提で描かれている。tile_0067 は家ではなく切妻屋根である。1タイルに屋根だけを置けば、屋根だけが見える。

建物は論理的には1タイルを占めたまま、描画だけを上へ1タイル伸ばす。既存の行単位の深度ソート（`objectDepth`）がそのまま機能する。

ただし副作用がひとつある。屋根は一行上に描かれながら自分の行で並ぶため、その一行上にある物を覆う。木でも、後ろを歩く住民でも、真北に建つもう一軒の戸口でもだ。これは手前が奥を隠すという、見下ろし視点として正しい振る舞いである。屋根を一行上でソートし直せば重なりは解けるが、今度は建物が自分の覆っているタイルより後ろへ回る。二つの不具合のうち、後者のほうが目に付く。

| 建物 | 屋根 | 壁・扉 | 添え物 |
| --- | --- | --- | --- |
| 住居 | tile_0067（赤い切妻） | tile_0086（扉） | — |
| 共同穀倉 | tile_0063（青灰の切妻） | tile_0074（大きな戸口） | tile_0116（熊手） |
| 穀物市場 | tile_0055（赤屋根・明かり取り） | tile_0075（壁） | tile_0093（穀物） |
| 配給所 | tile_0051（灰屋根・明かり取り） | tile_0078（灰の戸口） | tile_0083（木札） |

戸口の大きさと屋根の色で、穀物を溜める場所、売る場所、配る場所が離れて見ても区別できる。集積所は蜂の巣をやめ、tile_0130 の籠と tile_0106 の丸太を並べる。木も食料も同じ場所に積まれることが、二つの物で分かる。

添え物のタイルは実物を拡大して選んだ。名前や番号から推測すると外れる。tile_0095 は掲示板ではなく的であり、tile_0106 は俵ではなく丸太である。前者は配給所の目印として意味を成さず、後者は穀倉ではなく木材の側に属する。

### 4.3 小道は道として描く

現在は摩耗レベルごとに幅と色を変えた角丸の棒を1タイルずつ並べ、右隣にだけ橋を架けている。縦に続く道は数珠つなぎの塊になり、交差点はつながらない。

代わりに、摩耗レベルごとに帯を1枚のマスクとして組み立てる。各タイルに角の丸みを抑えた帯を置き、上下左右のうち踏まれている隣へは矩形で橋を架ける。同じ処理で直線は直線に、交差点は交差点になる。土の色はタイル素材から抽出した実際の土色を使い、定着した小道は暗く広く、踏み跡は淡く細くする。

摩耗の粒（小石）を決定論的な位置に少し撒くと、単色の帯にならない。

### 4.4 季節を地図に出す

`seasonOfTick(tick)` は `@agent-town/shared` の純粋関数で、クライアントは `world.tick` から季節を導ける。プロトコル変更は要らない。

一年は8日、実時間で約32分。季節は約8分ごとに変わる。

Tiny Town には緑と紅葉が同じ輪郭で描かれた木が三対ある。0016と0015、0028と0027、0004と0003。緑の側だけを季節で差し替えれば、構図を変えずに秋が来る。

- 春・夏: 0016 / 0028 / 0004
- 秋: 0015 / 0027 / 0003
- 冬: 秋の三枚をそのまま使い、彩度を落として青へ寄せる。地面には白い粒を撒く

冬の色を落とすのは葉にも効かせる。地面だけを寒色にして木を紅葉のまま残すと、雪の積もった秋にしか見えない。橙を抜いて青へ寄せた輪郭は、葉を落とす前の木が霜をかぶった姿として読める。一方で資源の目印（きのこ・若芽）は季節に関わらず彩度を保つ。採れる物が季節ごとに見えにくくなるのは、情報を増やすという目的に反する。

三対あるということは、季節とは別に樹形の変化も手に入る。現在は森のすべての木が tile_0016 一枚で描かれている。位置の安定ハッシュで三種を配れば、森が森の形になる。冬に木材を燃やす仕様（`burnWinterWood`）は、画面が寒くなることと噛み合う。

### 4.5 誰が誰かを保つ

スプライトは配列位置ではなく `agent.id` の安定ハッシュから選ぶ。

tiny-dungeon の人型タイルは13枚。ただし全部は使えない。0087 は角つきの兜、0096 と 0097 は面頬を下ろした甲冑、0109 は単眼の異形、0110 は赤い怪物、0111 は赤目の獣である。麦を刈り、冬に薪を燃やす集落に騎士が二人混じると、別のゲームの絵になる。残る8枚——0084 の紫の帽子の魔法使い、0085 と 0098 の村人、0086 と 0088 の労働者、0099 の女、0100 の白髪、0112 の緑衣——を住民の顔とする。現在使っているのは3枚である。

`MAX_POPULATION` は10なので、集落が満員のとき顔は二つ重なる。重複そのものは問題にならない。壊れているのは同一性のほうで、必要なのは全員が別人に見えることではなく、同じ人がいつ見ても同じ顔でいることである。

運搬物は黄色い四角をやめ、木材なら tile_0106、食料なら tile_0093 の小さなアイコンを住民の脇に描く。

### 4.6 影

住民・木・建物・集積所の足元に半透明の楕円を敷く。オブジェクトが地面に乗る。

### 4.7 住民は歩く

サーバーは毎ティック、1秒に10回状態を配信する。1タイルの移動に要するのは平地で3ティック分の前進量で、踏み固められた小道ではより少なくて済む。ただしこれは経過ティック数そのものではない。疲労が閾値を割った住民は1ティックあたりの前進量が半分になるため、同じ平地の1タイルに6ティックかかる。クライアント側の補間は、1タイルの所要時間を固定値として持ってはならない。クライアントには既存の `app.ticker` コールバックがあり、ダーティな世界レイヤーの描画、吹き出しの期限切れ、情報吹き出しと画面レイヤーの描画を毎フレーム処理している。

ところが `renderAgentLayer` が動くのは、サーバー更新で `agentsDirty` が立ったときだけである。そのたびに住民のコンテナを全破棄し、権威タイル位置へ作り直すため、住民は16ピクセルずつ跳び、フレーム間に動きを引き継げない。

住民のコンテナを `agent.id` で保持し、フレームごとに権威位置へ寄せる。移動そのものはサーバーが決めたままで、描画位置だけが追従する。深度は寄せた位置ではなく権威タイル行から取る。そうしないと、補間が二人の前後関係をひっくり返す。

移民が集落の端に現れたときのような大きな飛びは、補間せずに瞬間移動させる。歩いていないものを歩かせない。

## 5. 制約

- クライアントはゲームロジックを持たない。季節も摩耗も、既存の状態から導出するだけにとどめる。
- 新しい依存パッケージを足さない。素材は `packages/client/public/assets` の264枚に限る。
- 追加のスプライトは `SPRITE_PATHS` に登録し、起動時のプリロードに含める。
- タイルの選択は `sprites.ts` に集約し、各定数にそのタイルが何を描いているかのコメントを付ける（既存の規約）。
- 地形と小道の描画はタイル数に比例する。世界地図の生成をCIに載せるために払った最適化（S4）を壊さないよう、再描画は既存のダーティフラグ経由に限る。

## 6. 受け入れ基準

- 木を伐った森のタイルが、草原のタイルと見分けられる。
- 岩場と水面が、歩けない土地として見分けられる。
- 家が屋根だけに見えない。三施設が互いに区別できる。
- 直線の小道が直線に見え、交差点がつながって見える。
- 森の木が一種類でなく、季節が変わると樹種と地面の色調が変わる。
- 住民が餓死しても、生き残った住民の見た目が変わらない。
- 住民が隣のタイルへ跳ばず、歩いて移る。移民の出現は歩行に見せない。
- `just check` と `just test` が緑のまま、`pnpm --filter @agent-town/client build` が通る。

## 7. 前提条件（V3の範囲外だが、V3の成果を左右する）

この仕様は「地図が中身に追いついていない」という前提で書いた。公開ビルドを実測したところ、前提のほうが甘かった。中身が動いていない。

seed を5つ変えて12,000ティック（実時間20分相当）ずつ走らせた結果は、どれも同じである。

| | seed 1 | seed 7 | seed 42 | seed 1337 | seed 20260727 |
| --- | --- | --- | --- | --- | --- |
| 住民 | 3 | 3 | 3 | 3 | 3 |
| 家 | 0 | 0 | 0 | 0 | 0 |
| 施設 | 0 | 0 | 0 | 0 | 0 |
| 共同体 | 0 | 1 | 0 | 0 | 0 |
| 制度 | 0 | 0 | 0 | 0 | 0 |

起点は木材の2単位である。

`FakePlanner` の `resourceTasks` は、木材が冬の備蓄量に届いた時点で伐採をやめる。住民3人なら `3 × WOOD_BURN_PER_AGENT_PER_DAY × DAYS_PER_SEASON` で12。実際には一度の運搬が刻みを持つので25まで行き過ぎて、そこで止まる。

一方 `newHouseTasks` が家を建て始める条件は `HOUSE_WOOD_COST + winterWoodTarget`、つまり `15 + 12` で27である。

25は27に届かない。12,000ティック走らせても木材は25のまま動かない。伐採をやめる線と、家を建て始める線のあいだに2の隙間があり、住民は自分の建築条件に永久に手が届かない。

そこから先は自動的に閉じる。家が建たないので `hasImmigrationCapacity`（完成した家 × 2 > 人口）が偽になり、移民が来ない。人口は3で固定される。人口3に対して食料は70前後あり、日量12.5で割ると5.6日分になる。これは `INSTITUTION_FOOD_PRESSURE_DAYS`（4日）を上回るので `establishEligibleInstitutions` は即座に戻る。制度が生まれず、施設も生まれない。

したがって描くべきものが存在しない。

この行き詰まりは S5 が持ち込んだものではない。しきい値を決めている2行は `main` と現ブランチで1バイトも違わず、関係する定数もこのブランチでは変更されていない。`be7181e feat(sim): houses rest and immigration` の時点から入っている。

V3の8タスクはすべて、建物と施設と小道のある集落を描くために書かれている。この状態のまま実装すると、緻密に描き分けられた草原が出来上がる。**V3の着手より先に、この2の隙間を埋めること。**S5とは別のチケットとして扱い、失敗するテストを先に置く。

## 8. 保留

素材をさらに増やす場合、Kenney の他のCC0パックを取り込む選択肢がある。外部からのダウンロードになるため、オーナーの承認を得るまでV3の範囲には含めない。
